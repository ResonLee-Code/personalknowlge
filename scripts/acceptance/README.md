# 真机验收脚本（Track E1）

把 E 节的**真机验收**从"照着文档手工再点一遍"变成一条命令：
用例定义在 [`cases.js`](./cases.js)（唯一事实来源），执行器是 [`run.js`](./run.js)，
macOS 侧的原语（**读 AX 树拿元素与坐标 + AXPress 点击 + 剪贴板粘贴 + 截图**）在
[`lib/ax-agent.js`](./lib/ax-agent.js)。

## 一条命令

```bash
scripts/acceptance/run.sh --preflight   # 先自检：工具 / 辅助功能权限 / 应用是否在跑
scripts/acceptance/run.sh               # 真跑，产出截图 + 结论表
```

其它模式：

```bash
scripts/acceptance/run.sh --list        # 列出 E 节 1–9 的用例
scripts/acceptance/run.sh --dry-run     # 只出结论表骨架（不碰界面，可在任何时候跑）
scripts/acceptance/run.sh --out /tmp/pkos-accept-1   # 指定输出目录
scripts/acceptance/run.sh --only 3,4    # 只跑第 3、4 条（调某一条时用；结论表里也只列这几条）
```

产物（默认落在 `docs/acceptance/<时间戳>/`）：

- `report.md`：结论表 + 逐条明细（每条用例一段，含每步的执行结果与证据）；
- `report.json`：机器可读的同内容；
- `*.png`：用例里 `shot` 步骤的截图。

> **报告进仓库、截图不进**（`.gitignore` 里有 `docs/acceptance/*/*.png`）：
> 每轮真跑都会重新生成 11 张 PNG（约 20 MB），进仓库会随发版一轮轮堆积；
> 要留某一轮的截图，单独 `git add -f docs/acceptance/<时间戳>/<文件名>.png`。

## 前提

1. **macOS**，且应用已经构建好并能启动（`pnpm tauri build --bundles app`）；
2. 给运行脚本的终端（或 Codex）**辅助功能（Accessibility）权限**：
   系统设置 → 隐私与安全性 → 辅助功能；
3. 应用**正在运行**（脚本只驱动已运行的实例，不负责启动/关闭）；
4. 用一个**临时知识库**（默认 `/private/tmp/pkos-acceptance`，可用
   `--workspace` 或环境变量 `PKOS_ACCEPTANCE_WORKSPACE` 改），别拿真库跑。

现场不用手工摆：真跑前脚本会自己**切前台、按 Esc 清掉残留弹层、确认目标工作区已打开**
（欢迎页时按「最近打开」里的路径点开；全新机器则自动新建）。现场不对就**中止且不出结论表**。

## 口径（与计划 §1.5 的落地纪律一致）

- **没验的不写成通过**：`--dry-run` 与未覆盖的步骤一律标「未执行」；
- **主观手感交给人**：像「拖拽跟不跟手」这类步骤标「🖐 待人工」，脚本不替人下结论；
- **第 10 条（首次启动放行）脚本不覆盖**：它只对"从网络下载的包"有意义，
  必须在一台干净机器上人工验（报告里会列出这一条与原因）；
- 脚本**不读凭据、不写工作区正文**，报告里只有步骤说明与文件路径。

## 真机验证状态

### 2026-10-15 第三轮：界面梳理（去重复 / 开关归位 / 区块折叠 / 图标栏）

- 结论：`docs/acceptance/20261015-<时间戳>/`（用例 1–9 + 新增第 11 条；
  跑之前 `pnpm tauri build --bundles app` 重出包，脚本只驱动已运行的实例）。
- 新增**第 11 条：界面梳理**——侧边栏开关同高、收起态图标栏（导航项都在、点一个真能跳）、
  分类 / 标签折叠、条目行不溢出列表栏；新增两个原语：
  - `expectInside`：**框套框**几何断言（AX 读不到透明度，但读得到坐标）——
    用来钉住"条目行没有比列表栏宽"（Radix `ScrollArea` 那层 `display:table` 会让行按内容撑宽）；
  - `selectOption` 改成**走键盘**（按下拉开菜单 → 连按 ↑ 回第一项 → ↓ 到目标 → 回车），
    并且**隔 2.5 秒复核一次**。
- ⚠️ **这一轮又抓到一个"假通过"，值得单独记**：`selectOption` 早先的实现是"AXPress 点菜单项"，
  它确实能让 `<select>` 的 DOM `value` 变掉、验证也读得到新值——**但 React 收不到 change 事件**，
  app 的状态根本没变，下一次渲染还会把值弹回去。报告写"已选 ✅"、工作区里却还是旧值。
  现在：走键盘（真人操作菜单的方式）＋ 延迟复核。**教训：验证要盯"app 的效果"，不是"DOM 的样子"。**
- 另一条现场纪律：**跑验收时别碰这台电脑**。实测跑着跑着 Codex 窗口把前台抢走，
  元素的查询/点击随即失败，报告会写成"功能失败"——其实只是**现场没保持住**。
  现在每条用例开始时会自动把应用切前台（`runCase` 里一次），步骤级不再逐个切（太拖时间）。
- 新增两个原语：`expectSize`（元素尺寸在范围内——用来钉"大纲栏头不许变两行"）、
  `expectInside`（框套框——钉"条目行没有比列表栏宽"）。失败时 `expectInside` 会**顺带报出
  这一栏当时是什么态**（列表栏=大纲 / 列表栏=列表 / 正文右侧=大纲），省掉一轮排查。
- ⚠️ **一个只在本机 WebKit 上出现、还没解释清楚的现象**：跑用例途中，"这一栏显示列表还是大纲"
  有时会自己变回大纲（同一条用例里 `ensure` 会报告"又按了一次才回到列表"）。
  同一套代码在 Chromium（`pnpm test:e2e`）下**不复现**（新建笔记不会改栏位）。
  目前的处理是让用例**自己把前提摆正**（每个依赖栏位的动作前先 `ensure`），
  并在报告里如实记下"按了几次"——不把它当成"功能坏了"，也不假装没发生。
- 🖐 **第 9 条的前提只能人工准备**：设有效期的控件是原生 `<input type="date">`，
  在无障碍树里**完全不可见**（连 role 都没有；Tab 走过去再敲数字也写不进去，实测两轮）。
  验收库里因此常驻一篇手工准备的 `00_Inbox/…验收-待复核笔记.md`（`valid_until` 已过期）；
  卡片与「已过期」角标两条断言仍是机器判定。**换新验收库时要先手工准备这一篇**。

### 2026-10-15 第二轮：界面改完再跑（V1.3.0 布局调整之后）

- 结论：`docs/acceptance/20261015-084618/`，**自动步骤 95 步通过 / 0 步失败**
  （上一轮 71 步；多出来的步数来自重写后的第 4 条——它把"大纲的每一处位置"逐步走一遍）。
  中间那一轮 `docs/acceptance/20261015-080853/`（84 步）也留着：它跑在把 mini/悬停也自动化之前。
- 第 4 条按新界面重写：先用设置页把**前提**摆回默认（`大纲位置` = 与笔记列表共用一栏）→
  这一栏切到大纲（同一栏切换，栏头出现「返回笔记列表」）→ 挪到正文右侧（列表栏还给列表）→
  **贴边 mini → 悬停展开 → 钉住** → 再挪回列表栏，每一步都有元素级断言（成对用到 `expectAbsent`）；
  截图 `04-outline-in-list.png` / `04-outline-side.png` / `04-outline-mini.png` /
  `04-outline-hover.png` / `04-outline-split.png`。
  起点**不再假定**"工作区里的大纲位置一定是默认值"（`大纲位置` 是工作区级偏好，会被上一轮残留改掉；
  见下面第 3 条）。
- ✅ **这一轮又暴露并修掉三类"脚手架自己的"缺陷**（同样不是应用的问题，但都会让报告说谎）：
  1. **`role` 写错 + 子串匹配 = 点到别的东西**：带 `aria-pressed` 的按钮在 WebKit 里是
     `AXCheckBox`（名字在 `description` 上），旧用例的 `{ role:'AXButton', title:'大纲' }`
     一直**按子串命中了右侧面板的「收起大纲」**——报告写着 ✅，点的却不是用例想点的那个。
     教训：**"步骤通过"不等于"点的就是它"**，查询要精确到 role。
  2. **AXPress 返回成功、界面却不动**：导航刚发生时无障碍树里还留着**上一页**的同名元素，
     React 节点已经卸载，点击被静默丢弃（实测失败率约 1/2，屏幕上看不出任何异常）。
     修法是给执行器加原语 `ensure`（**以界面状态为准**：目标不在就按一次控件再查，最多 N 次，
     **按了几次如实写进报告**）与 `expectAbsent`（成对地断言"界面上确实没有"）。
  3. **用例的"前提"也是会变的**：`大纲位置` 是**工作区级偏好**，被上一轮残留改掉之后，
     "默认在列表栏"这个前提就不成立了。所以用例要能**自己把前提摆好**——又加了 `selectOption`
     （改原生下拉，改完读 `value` 复核）；同时补了 `hover`（真实鼠标移动），
     把"贴边 mini 态悬停展开"从「🖐 待人工」变成机器证据。
  这三条合起来就是那句老话：**"改了界面就要顺手跑一次这条命令"**——界面一改，用例里那些
  "照记忆写的名字、role 与前提"都会悄悄失效。
- 新增 `--only 3,4`：只跑指定用例（调某一条时用，结论表里也只列跑过的那几条）。

### 2026-10-14 首次实跑

- ✅ **AX 那一层已经在真机上跑通**：`docs/acceptance/20261014-212209/` 是本机跑出来的结论表（旧轮次移到 `src-tauri/target/acceptance-archive/`，不入库），
  **自动步骤 71 步通过 / 0 步失败**（用例里的人工确认步骤仍按「🖐 待人工」列着，见下）。
  驱动器能：切前台、按路径打开工作区、AXPress 点击按钮/链接/输入框、用剪贴板输入中英文、
  发应用快捷键（⌘N / ⌘P / ⌘E / ⌘S）、截图，并做**文件级断言**（笔记落盘、备份 zip、history 目录、
  research 会话是否存在、**网页剪藏真的抓回并落盘**）与**元素级断言**（首页「待复核」卡片在不在）。
- ✅ **首次真跑暴露并修掉了 5 个"脚手架自己的"缺陷**（都不是应用的问题，但都会让报告说谎）：
  1. **AX 读取全程失效**：JXA 里属性名不桥接成 `CFString` 会返回 `-25201`，桥接后又拿不到
     `Ref()` 输出参数（得到不可解引用的对象）→ 整棵树读成一个节点、任何元素都"找不到"。
     改走 `System Events` 读树；
  2. **没有现场准备**：应用停在欢迎页时，后面每条用例的第一次点击全落空 →
     报告写成"6 条失败"，把**现场没准备好**说成**功能有问题**。现在现场自己摆，摆不好就中止；
  3. **无障碍树会被 WebKit 收起来**：没有 AX 客户端持续轮询时，树只剩窗口边框三个按钮。
     真跑期间由 `lib/ax-keepalive.js` 保活；
  4. **坐标点击在这个 WebView 里不生效**（补 `kCGMouseEventClickState` 与按下/抬起间隔也没用），
     而 `AXPress` 有效；中文用 `keystroke` 会进输入法候选窗，必须走剪贴板粘贴。
  5. **`mac.click` 漏传应用名** → 代理侧按名字找不到进程 → "查元素"永远失败 →
     每一次点击都**静默退化成按坐标点**（报告里照样写 ✅，因为点击本身返回成功）。
     这个是修完前 4 条之后才暴露出来的：修好后 15 次点击**全部走 AXPress**（0 次坐标兜底）。
     教训写在这里：**"步骤通过"不等于"动作生效"**——所以每条用例都配了文件/元素级断言。
- 🖐 **只能人眼判断的仍标「待人工」**（脚本不替人下结论）：拖拽跟不跟手、原生导出/选目录面板、
  真实联网剪藏与联网检索、报告 diff 与角标文案的语义核对。
- ⚠️ **用例是照着"记忆里的界面"写的**，首次真跑 6 条失败大多只是**名字对不上**
  （侧边栏是 `AXLink` 不是 `AXButton`、大纲按钮叫「收起大纲」、「更多操作」是 `AXPopUpButton`）。
  `cases.js` 已按真实 AX 树改写；**改了界面就要顺手跑一次这条命令**，否则它会默默过期
  （2026-10-15 第二轮又验证了这一点：布局一改，第 4 条的前提与名字全都不成立了）。
