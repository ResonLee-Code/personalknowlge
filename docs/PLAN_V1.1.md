# 下一阶段计划（V1.1）

上一阶段的成果与流程见 [CHANGELOG.md](./CHANGELOG.md)；
本文只回答「接下来做什么、做到什么程度算完成、需要你确认什么」。

## 1. 阶段目标

> 让「记录 → 组织 → 找回」形成闭环，并让笔记之间产生关系。

V1.0.1 解决了「能记、能搜、能带走」；V1.1 的重点是
**双向链接与反向链接（知识图谱 M1）** 为核心，配合三项高频体验补齐
（图片粘贴、大纲与快速切换、模板），并完成 Windows 侧的发布验证。

## 2. 范围

### 本阶段做

| 编号 | 能力 | 优先级 | 说明 |
| --- | --- | --- | --- |
| F1 | 双向链接数据层 | P0 | 新增 `note_links` 表与解析器：`[[标题]]`、`[[标题\|别名]]`、`[[标题#小节]]`、相对 Markdown 链接；忽略代码块内的 `[[…]]` |
| F2 | 反向链接面板 | P0 | 编辑器内显示「谁引用了我」+ 上下文摘要，可点击跳转；元信息栏显示「被 N 篇引用 / 引用 M 篇」 |
| F3 | 未解析链接 | P0 | 全库未解析链接列表，一键创建目标笔记并自动建立连接 |
| F4 | 链接重建与联动 | P0 | 保存/导入/外部修改增量更新；重命名自动重连、删除标记失效、恢复复活；`links_rebuild` 全量重建 |
| F5 | 编辑器双链体验 | P1 | 输入 `[[` 触发标题补全；预览态渲染为可点击 chip；搜索结果标注「被 N 篇引用」 |
| F6 | 图片与附件粘贴 | P1 | 编辑器粘贴/拖拽图片自动落盘到 `attachments/`（按年月分目录），插入相对路径链接并同步索引 |
| F7 | 大纲与快速切换 | P1 | 编辑器右侧大纲（解析标题层级、点击滚动）；`⌘/Ctrl + P` 按标题模糊跳转 |
| F8 | 模板 | P1 | 本地模板目录（`.knowledge/templates/*.md`）+ 新建时选择；支持日期/标题占位符 |
| F9 | Windows 发布验证 | P0（发布门槛） | 按确认后的版本重新交叉编译 + NSIS 打包，并在真实 Windows 上跑验收清单（安装、启动、文件读写、快捷键、卸载） |

### 本阶段不做

- 云端同步、账号体系、成员权限、评论、多人实时协同、移动端、多维表格；
- 语义检索与 AI 摘要（留在 V3.0，且必须可关闭、可离线）；
- 自动更新与代码签名（需要证书与外部服务，单独立项，见第 5 节）。

### 可选（视数据规模与反馈决定）

- 中文分词增强：若 1 万笔记下索引体积或召回率不理想，再评估自定义分词或预分词字段；
- 保留目录结构的导入、网页剪藏（浏览器扩展）；
- 版本历史（基于 `content_hash` 的本地快照 + 差异对比）。

## 3. 里程碑

### M1 · 双向链接地基（P0）

- **交付**：迁移 `003_note_links.sql`；`LinkService`（解析、增量更新、全量重建）；
  命令 `links_get_backlinks`、`links_get_outgoing`、`links_get_unresolved`、`links_rebuild`；
  编辑器「反向链接」面板；元信息栏引用计数。
- **涉及模块**：`infrastructure/fts`（同一写入时机）、`application/link_service`、
  `repositories/link_repository`、`components/editor/BacklinkPanel`。
- **验收**：写出 `[[A]]` 后 A 的反链立即出现；重命名 A 后链接自动重连；
  删除 A 后反链标记失效、恢复后复活；重建索引后链接与正文一致；
  1 万笔记重建 < 10 s（后台线程 + 进度事件）。

### M2 · 编辑体验（P1）

- **交付**：`[[` 自动补全、chip 渲染与跳转、搜索结果引用计数、图片粘贴落盘、编辑器大纲、`⌘P` 快速切换、模板。
- **验收**：粘贴截图为附件并插入相对路径；大纲点击可滚动到对应标题；
  `⌘P` 输入两三个字即可定位目标笔记；模板创建的笔记 frontmatter 正确。

### M3 · 知识图谱视图（P2，可延后到 V1.2）

- **交付**：`graph_get`（节点 + 边 + 过滤）；`/graph` 页 Canvas 力导向布局；
  分类着色、度数定大小、1–2 跳聚焦、分类/标签/时间过滤、孤立节点开关。
- **验收**：3000 笔记首屏 < 1.5 s，交互 ≥ 30 fps；默认最多渲染 2000 节点 / 5000 边并提示先筛选。

**状态（2026-10-07）**：✅ 已完成（用户指令提前到 V1.1.0）。`graph_get` 支持分类/标签/关键词/
孤立节点/聚焦 1–2 跳与容量截断；`/graph` 页自研 Canvas 力导向布局（无第三方依赖），
收敛后停止渲染帧；时间过滤暂未做（保留 `updatedAfter` 参数位，界面未暴露）。

### M4 · 发布与打包（P0 发布门槛）

- **交付**：版本号统一（`package.json` / `Cargo.toml` / `tauri.conf.json` / CHANGELOG）；
  macOS `.app` + `.dmg`；Windows NSIS 安装包 + 便携版；两端验收清单逐项记录。
- **验收**：Windows 与 macOS 上「安装 → 启动 → 建库 → 记录 → 搜索 → 导入导出 → 卸载」全部通过；
  卸载不删用户知识库；备份包可校验。

## 6. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 双链解析引入性能回归 | 保存变慢、重建耗时长 | 解析与索引同事务、重建异步；把 1 万笔记基准测试纳入验收 |
| 链接表成为第二数据源 | 与正文不一致 | 明确定义为**可重建派生数据**，`links_rebuild` 一键修复并纳入验收 |
| 图片附件膨胀工作区 | 体积增长、备份变慢 | 按年月分目录、附件清单纳入备份与导出校验 |
| Windows 产物缺乏真机验证 | 用户侧安装异常 | M4 强制真机验收清单；CI 在 `windows-latest` 上构建并跑测试 |
| 版本号/文档漂移 | 用户与协作方混淆 | 「文档同步规则」：每次提交更新 CHANGELOG 与相关文档，版本号三处一致 |

## 7. 完成定义（Definition of Done）

一个 V1.1 任务只有同时满足以下条件才算完成：

1. 功能可用且有测试覆盖（Rust 单元/集成、前端单测，必要时 E2E）；
2. `cargo test --offline`、`pnpm test`、`pnpm lint`、`pnpm build`、`pnpm test:e2e` 全绿；
3. 文档同步：CHANGELOG + 受影响的 `docs/*.md`（API、UI、架构、路线）；
4. 提交信息说明「改了什么、为什么、如何验证」；
5. 跨平台产物更新前先取得确认，并记录验收结果。
