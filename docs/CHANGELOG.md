# 变更记录

本文件记录**用户可见的变化**（新增能力、行为调整、缺陷修复）。
每次功能或修复提交后必须同步更新本文件与相关设计文档，见
[DEVELOPMENT_RULES.md](./DEVELOPMENT_RULES.md) 的「文档同步规则」。

版本号同时存在于 `package.json`、`src-tauri/Cargo.toml` 与 `src-tauri/tauri.conf.json`，
发布前必须保持一致。

---

## V1.2.1（未发布）

主题：**文档目录树 + 条目操作菜单 + 大纲预览**，并修掉两个已确认缺陷。
本版把「一篇笔记」升级为「一个可以套子文档的文档」，向语雀的目录使用习惯靠拢，
同时仍然只依赖本地 Markdown（父子关系写在子文档 frontmatter 的 `parent:`）。

> 版本号暂未改动（仍为 1.2.0）：打包与发版等确认后再统一升到 1.2.1。

### 子文档层级（迁移 007）

- `notes` 新增 `parent_id` 列（迁移 `007_note_parent.sql` + `idx_notes_parent`），
  `SCHEMA_VERSION = 7`；该列是**派生数据**，由子文档 frontmatter 的 `parent:` 投影而来，
  删除 `.knowledge/database.sqlite` 后可完整重建；
- `parent:` 可写父笔记 **id**（稳定）或**标题**（手写友好，忽略大小写按更新时间取第一条）；
- 新增命令 `note_set_parent`（`{ input: { id, parentId } }`，`parentId = null` 移到顶层），
  带防环校验（沿父链上溯，命中自身或 > 64 跳直接报 `INVALID_INPUT`）；
- `note_create` 支持 `parentId`（id 或标题），并且**未显式指定分类时继承父文档分类**；
- 父文档被删除或重命名后子文档保持稳定：派生列指向失效时不隐藏笔记，按顶层展示；
  重命名父文档会同步子文档的 `parent:` 声明；
- 外部编辑（文件监听 / 扫描 / 导入）后自动重算父子关系，`adopt_files_batched` 在批次结束
  统一解析，避免逐文件重建标题索引；
- 测试：`src-tauri/tests/parent_flow.rs` 3 个集成测试（创建继承分类与 frontmatter 落库、
  set_parent 跨层级 / 防环 / 移回顶层、父文档重命名与删除后子文档稳定）。

### 笔记列表（对标语雀）

- **拖拽建立层级与同层排序**：把条目拖到另一条的**中间**即成为它的子文档（蓝色框提示），
  拖到**上下边缘**则插到该位置（蓝色横线提示，对标语雀的拖拽语义）；
  拖进自己或自己的子树会被拒绝；
- **自定义顺序**：新增「自定义顺序」排序（`order` 落 frontmatter + `notes.sort_order` 派生列，
  迁移 008）。拖拽排序会自动切到该顺序并提示；顺序按**层**归一化，未拖过的同层笔记保持原相对顺序；
  排序不修改 `updated_at`（不算内容改动），删库重扫可从 Markdown 重建；
- **排序偏好会记住**：列表排序随工作区设置持久化（`listSort`），重开应用或切换知识库后
  仍是上次的选择——「自定义顺序」尤其需要，否则拖出来的顺序下次打开就看不到；
- **「不在目录中」筛选**：工具条新增该开关，只看没有被任何父文档收纳的顶层文档，
  对齐语雀「移出目录 → 全部文档 → 状态筛选：不在目录中」的找回路径；
- **删除可撤销**：单篇删除与批量删除的提示都带「撤销」，点击即从回收站恢复
  （批量撤销只恢复成功删除的那些）；
- **置顶文档**（对标语雀「置顶文档」）：条目菜单新增「置顶 / 取消置顶」，
  置顶写回 frontmatter 的 `pinned: true`（迁移 009 投影成派生列），
  **在所有排序方式下都排在最前**；条目元信息显示「已置顶」；
  注意子文档仍跟在父文档下（置顶只在同一层内生效，不会把子文档拽到顶层）；
- 置顶与拖拽排序都**不改写 `updated_at`**，不影响「最近修改」的语义；
- **批量复制到分类**（对标语雀条目菜单的「复制…」）：多选工具条新增「复制到」，
  复制出的副本落到目标分类，**原作保留**（副本标题带「副本」后缀、保留标签与父文档）；
- **目录整树折叠**：工具条新增「折叠全部 / 展开全部」（仅在存在子文档时出现）；
- **复制相对路径 / 复制标题**：条目菜单新增两项（语雀「复制链接」在本地知识库的对应物）。
- **标题悬停显示完整标题**：长标题被 `truncate` 截断时，悬停显示完整标题（Radix Tooltip 走
  传送门，不被滚动容器裁切）——修复「标题遮挡时看不到完整内容」；
- **条目操作菜单支持 `⋮` 与右键双入口**，内容对齐语雀：打开 / 收藏 / 创建子文档 /
  升级为顶层文档 / 大纲预览 / 重命名 / 移动分类 / 导出（MD·HTML·Word·PDF）/ 创建副本 /
  移到回收站（回收站内为恢复 / 永久删除）；
- **目录树展示**：父文档带展开 / 折叠箭头与「N 篇子文档」计数，子文档缩进显示；
  折叠状态只在当前会话内记忆。父文档不在当前筛选结果里时，子文档按顶层展示，
  frontmatter 手写出环时也不会死循环或丢笔记（`src/lib/noteTree.ts`）。

### 大纲目录预览

- 列表条目菜单「大纲预览」：不打开文档即可查看该笔记的标题层级，
  点击条目会打开笔记并**跳转到对应标题**（URL 携带 `?h=<偏移量>`，编辑器消费后清除参数）；
- 纯预览模式下会先切到分屏再跳转；正文没有标题时给出书写引导。

### 编辑器（P2 对标语雀）

- **大纲「钉住 / mini 态」**：编辑器大纲现在有三态——固定（钉住）、贴边收起（mini）、隐藏；
  点面板里的「收起大纲」变成右侧贴边条，鼠标移上去临时悬浮展开（绝对定位，不挤压正文），
  再点「钉住大纲」固定回右侧；
- **另存为模板**（对标语雀「另存为模板」）：编辑器「更多操作 → 另存为模板…」把当前正文
  存进 `.knowledge/templates/<名字>.md`（正文没有一级标题时自动补 `# {{title}}`），
  下次「新建笔记 → 模板」即可复用；同名默认要求显式勾选覆盖，模板名做了路径与非法字符校验；
- 工具条在窄列表下改为整齐换行（此前「标题」「自定义顺序」会被掰成两行）。

### 版本历史（P2 对标语雀「查看历史版本」）

- **自动留档**：每次「保存前」把旧内容存成快照，落在工作区内
  `.knowledge/history/<笔记 id>/<时间戳>-<哈希>.md`（普通 Markdown，可直接用其它编辑器查看）；
  同一篇 60 秒内只留一份（自动保存每秒都会写，不节流会瞬间堆出上百份），每篇最多 50 份；
- **只记真正的改动**：正文没变时不重复留档（否则快照会堆成「当前内容」，还原等于没还原）；
- **历史版本对话框**：编辑器「更多操作 → 历史版本…」列出快照（时间 + 正文预览），
  可对比**任意两版**（左侧选基准、右侧选目标，「当前版本」也可作为目标），
  差异按行着色并给出 `+N −M` 摘要；支持删除单个快照；
- **还原**：只回滚**正文**，标题 / 标签 / 分类 / 父文档等元数据保持当前值
  （避免「回滚内容」意外把改过的标题也退回去）；还原前会把当前内容强制留档，可再回滚；
- 永久删除笔记时一并清理它的历史目录，不在 `.knowledge/history` 留孤儿数据；
- 新增命令：`note_history_list` / `note_history_read` / `note_history_restore` / `note_history_remove`。

### 导入：Word / CSV（P2 对标语雀的 Word·Excel 导入）

- 新增 `.docx` 与 `.csv` 导入（`application/import_office.rs`）：
  - `.docx`：解压 `word/document.xml`，按段落抽取文本；段落样式 `Heading1~6` / `标题1~6`
    映射成 Markdown 标题、列表段落映射成 `- `，实体（`&amp;`、`&#65;`）正确还原，
    连续 run 会拼接成一段；
  - `.csv`：按 RFC 4180 解析（引号包裹、字段内逗号与换行、`""` 转义），生成 Markdown 表格，
    单元格里的 `|` 会被转义；超过 5000 行时截断并在文末标注；
- 依赖取舍（评估结论）：只用**已有**的 `zip` + 本地缓存的 `quick-xml` 抽文本骨架，
  不引入 `calamine` / `docx-rs` 这类大包；**docx 里的图片、表格、批注、页眉页脚不导入**，
  这是有意的取舍（可预期、零新增大依赖），需要完整保真时应改用其它工具转换后再导入；
- 文件选择器与导入说明同步支持 `.docx` / `.csv`；标题去掉扩展名。

### 交叉验证：冲突并列与不选边（阶段 D4，2026-10-11）

按 §9.3 / §9.4 补齐「来源之间矛盾时**并列呈现、不选边**」，并明确时效口径的现状：

- **冲突判定（规则档）**：同一子问题下的来源同时出现「支持性表述」（支持 / 推荐 / 适用 /
  可行 / 有效…）与「反对或限制性表述」（不支持 / 风险 / 限制 / 避免 / 失败…）即判为存在冲突；
  判定只看**同一子问题内部**，避免把不同角度的材料误判；
- **呈现纪律**：冲突的子问题**不进结论段与关键事实段**（既不选边也不当事实），只落在
  「3. 争议与不确定性」段并附引用，同时在报告顶部给出**醒目冲突警告**；
  报告第 3 段的占位文案相应改为「规则档说明」（不再是「等 D4」）；
- **时效**：报告已按要求记录 `published_at` / `fetched_at`，超出时间窗或 `valid_until` 已过
  的来源标「可能已过时」并在警告块列出；写入知识库时 `valid_until` 默认 +180 天，
  笔记侧的过期角标沿用 N1（元信息栏）；
- **测试**：`research_flow.rs` 增 1 项（对立来源 → 冲突段呈现、不进结论段、警告可见、
  不出现「未检出冲突」占位）；`research.rs` 增 1 项极性/冲突判定单测（保守性：
  只有一面不判冲突、单条来源不可能冲突）；mock 端同表实现并在报告第 3 段渲染冲突；
- **仍未做（如实告知）**：`valid_until` 到期的**主动复核提醒**（首页/列表层的待复核入口，
  属于 N3 生命周期）；语义级冲突比对与置信度打分要等模型 / Jev（D5）。

### 联网检索（阶段 D3，2026-10-11）

按 §9.5 / §9.7 接入**外部检索**，同时保持「默认不外发」的口径不变：

- **不预置任何第三方检索服务**：检索源地址在「设置 → AI → 检索源地址」由用户配置
  （URL 模板，必须含 `{query}`，可选 `{limit}`；只接受 http(s)，不合法即视为未配置）；
  响应支持 SearxNG `format=json`、`{ "results" | "items" | "data": [...] }` 与裸数组三种形状；
- `web_search` 真实接入（`ai_web_search` 增加 `confirmed`）：顺序仍是
  总开关 → 联网档位 → 本次确认 → 域名黑白名单（**检索源本身也受域名规则约束**）→ 发一次请求；
  未配置检索源时**不发起任何请求**并如实报错；成功/失败都写 `outbound=true` 的审计（不含正文）；
- **研究收集接入外部来源**：允许联网 + 本次确认 + 已配置检索源时才检索；命中材料按 §9.3 规则
  分级（域名内置表 → 内容自证 → 兜底「弱」），带 `published_at` / `fetched_at`；
  抓正文受「允许抓取正文」开关约束，失败退回检索摘要；预算同时限制**检索条数**与**抓取页数**，
  并按 `maxDurationSecs` 计时中断；
- **注入防护**：抓来的文本按「数据」处理，命中明显的提示词注入特征（例如
  `ignore previous instructions` / 「忽略以上指令」/「不要告诉用户」）即**直接丢弃**并计入步骤日志
  （`web_search::looks_like_injection`，规则保守、可解释、可单测）；

### 目录分组：语义结论（阶段 C5，2026-10-11）

语雀的「分组」是目录里的**非文档容器**（能装文档、自己不是文档）。经核对当前实现，结论是
**不新增节点类型**——已有能力已覆盖组织需求，只补了可发现性：

| 语雀分组的能力 | 本应用的对应实现 | 证据 |
| --- | --- | --- |
| 目录里嵌套的容器，可折叠 | **子文档层级**（父文档 + 子文档，任意层深） | `lib/noteTree.ts` 递归建树；列表行带折叠箭头 |
| 把文档归到一个分组下 | 拖到条目中间即成为其子文档；条目菜单「创建子文档」 | V1.2.1 拖拽语义与 `note_set_parent` |
| 分组本身不承载内容 | 父文档**正文可以留空**（没有任何必填正文的约束） | `note_create` 只要求标题 |
| 分组的分类归属 | 子文档默认**继承父文档分类** | `NoteService::create` / CreateChildNoteDialog |

差异（如实记录）：语雀的分组不是文档、点不开；我们的「分组」本身是一篇（可为空的）文档，
因此它能被打开、被链接、被搜索——这是本地 Markdown 模型下的取舍，不额外造一种节点类型。
可发现性补强：新建子文档对话框的说明里明确写出「父文档也可以只当分组用（正文留空、标题写分组名）」。

### 知识图谱：大库抽样与查询提速（阶段 C2，2026-10-11）

**基准暴露的两个真问题**（`BENCH_NOTES=30000 cargo test --offline --test graph_bench -- --ignored --nocapture`）：

1. **全量查询 7.76 s**（M3 验收红线 1.5 s），且节点候选被**静默截断到 2 万**
   （分页循环的 `page >= 100` 上限，30k 库丢了 1 万篇）；
2. **抽样把图切碎**：按全局度数取前 2000 个节点后只剩 **407 条边**（库内 6 万条），
   用户看到的是散点而不是结构。

**本轮改动**：

- 节点候选：无过滤条件时改为**一次查询取全量**（`list_by_status`），不再逐页往返；
  有过滤（分类 / 标签 / 关键词）时按 500/页取完（上限 50 万兜底），移除 2 万的静默上限；
- 边加载：新增 `list_resolved_pairs` 只取 `(source, target, link_type)` 三列（大库省一半以上分配），
  边表键从 `BTreeMap` 换成 `HashMap`；
- **抽样策略改为「分类配额 + 连接优先」**（`sample_nodes`）：按分类规模分配名额（每类至少 1 个），
  组内以度数最高的节点为种子、**沿邻居向外扩张**填满名额，最后再用剩余节点按度数补足——
  既保证各分类都有代表，又让样本内部保留大量连接；
- 前端提示文案同步说明抽样口径（「每个分类都保留代表，并把高连接节点的邻居一起带进来」）。

**基准回归**：

### 稳定性：扫描与文件监听并发（阶段 B，2026-10-10）

**背景**：V1.1.0 的 3000 篇基准里定位过一条数据正确性缺陷——显式扫描与文件监听同时采纳
同一路径，触发 `UNIQUE constraint failed: notes.workspace_id, notes.file_path`，
两侧扫描互相中止（active 卡在 375）。当时的第一版修复（`scan_lock`）因锁序倒置回退，
CHANGELOG 里一直记着「修复待重做」。

**本轮结论：已收敛**（先复现、后验证，不靠猜）：

- 两条采纳路径都已在**同一事务内**做「路径已存在 → 跳过」的幂等守卫：
  `IndexService::adopt_file`（单篇）与 `adopt_files_batched`（批量，
  注释即写明「路径已被其它扫描采纳 → 跳过（幂等）」）；这是 V1.2.0「批事务化」时一并落地的；
- 本轮补上最后一个窗口：`NoteService::create` 改为**幂等落库**（写文件后若扫描已抢先采纳，
  同一事务内按路径确认并沿用已有行），避免「边扫描边新建」时撞主键导致创建失败；
- 新增并发测试 `src-tauri/tests/concurrency_scan_flow.rs`（3 项，屏障对齐同刻起跑）：
  ① 扫描 × 监听采纳同一批 400 篇；② 两个线程同时扫同一目录；③ 边扫描（102–310 轮）边新建 120 篇；
  全部通过且无 UNIQUE 冲突；
- 基准回归：3000 篇 `active == 文件数（3001）`、`links_rebuild 扫描 3001 篇 / 链接 6000 条 / 已解析 6000`；
  1 万篇 `已索引 10001 / 共 10001`、检索平均 18.5 ms / p95 44.7 ms、召回 100%（无退化）。

### 缺陷修复

- **还原 / 外部改动后编辑器仍显示旧内容**（做历史版本时暴露）：编辑器只在「切换笔记」时
  同步磁盘内容，同一篇笔记的内容被外部改动（历史版本还原、外部编辑器）后界面停在旧内容上，
  并且自动保存会把旧内容**写回覆盖**刚还原的版本。已修：编辑器改为按内容哈希同步
  （有未保存输入时不覆盖用户内容）、外部变更后重建编辑器实例、
  自动保存发现磁盘哈希已变时放弃本次写入；
- **切换知识库后 `/graph` 页不自动刷新**（V1.2.0 真机验收记录的缺陷）：
  图谱页现在监听当前知识库 id，切换 / 打开 / 新建知识库后自动重新查询，
  不再需要手动点「重新查询」；
- **外部编辑器改的 `order:` / `pinned:` 不生效**（本轮新增功能时发现的缺陷）：
  扫描同步路径只投影了来源与时效，漏了手动排序与置顶这两个派生列，
  导致用户手写 frontmatter 后要等到「删库重建」才生效。已在 `apply_external_edit`
  补齐两个投影，并加了集成测试覆盖「手写 `order: 7` / `pinned: true` 后重扫生效」；
- 顺带核实「状态栏 `invalid args 'input' for command 'settings_update'`」：
  该缺陷（Retina 小数像素导致后端反序列化失败）已在 V1.1.2 修复，本版无回归。

### 3000 篇基准与发现的三处缺陷（2026-10-07）

合成工作区：**3000 篇笔记 / 8 个分类 / 每篇 2 条出链（6000 条链接）**，脚本见
`src-tauri/tests/graph_bench.rs`（`cargo test --offline --test graph_bench -- --ignored --nocapture`）。

实测（修复前，macOS aarch64 本机）：

| 项目 | 结果 |
| --- | --- |
| 写入 3000 个 Markdown 文件 | 159 ms |
| 扫描采纳（含解析链接） | 28.9 s（新增 3000 篇，缺失 0） |
| `links_rebuild` | **51.7 s**（扫描 3001 篇 / 链接 6000 条 / 全部解析） |
| FTS 索引重建 | 1.55 s |
| `graph_get` 全量 / 分类过滤 / 2 跳聚焦 | 23.5 ms / 22.0 ms / 22.9 ms |
| `database.sqlite` / `.knowledge` 合计 | 6.7 MB / 10.8 MB |

基准暴露并已修复的两处缺陷：

1. **图谱节点被静默截断到 500**：`GraphService` 复用了 `NoteListQuery`，而列表查询单页上限 500，
   导致 3000 篇的库里图谱只返回 500 个节点（`truncated` 还是 false）。
   已改为按页取全量候选，再按 2000/5000 的图谱上限截断并正确置位 `truncated`；
2. **`links_rebuild` 退化为 O(N²)**：每篇笔记都重建一次标题索引（全表查询 + 建哈希表）
   并单独开事务，3000 篇下 51.7 s。已改为索引只构建一次、正文先读完、全部链接在**单个事务**内批量写入。

3. **扫描与文件监听并发不安全（已定位，修复待重做）**：文件监听回调走的是
   `IndexService::apply_file_changes`，它绕过 `scan_scope` 的「检查存在性 → 插入」序列；
   与显式 `scan_workspace()` 并发时，同一路径会被双方重复采纳，触发
   `UNIQUE constraint failed: notes.workspace_id, notes.file_path`，两侧扫描反复中止
   （复现：3000 篇时 active 卡在 375 —— 恰好一个分类目录的量）。
   第一版修复（`WorkspaceContext` 加 `scan_lock`，由 `scan_scope` / `apply_file_changes` /
   `NoteService::create` 共用）在基准下验证有效，但会让 `file_watcher_reports_external_changes`
   集成测试挂起（监听线程持锁后与主线程形成锁序倒置），因此**已回退**。
   下一版方向：扫描改为单飞队列（watcher 只投递事件、由同一工作线程串行消费），
   或让采纳路径对插入冲突幂等（冲突时按外部修改同步，而不是报错中止整轮扫描）。

下表「修复后」列是在**临时互斥锁生效的构建**上测得的（`links_rebuild` 与 `graph_get`
的数字只取决于已提交的两处修复，与锁无关；「扫描采纳」一行受锁影响）。回退锁之后，
基准的扫描步骤是时序相关的，可能再次触发上面的冲突 —— 待并发修复落地后统一复验。

| 项目 | 修复前 | 修复后（含临时锁） |
| --- | --- | --- |
| 写入 3000 个 Markdown | 159 ms | 158 ms |
| 扫描采纳 | 28.9 s | 28.4 s（新增 3000，缺失 0） |
| `links_rebuild` | **51.7 s** | **471 ms**（≈110×，O(N²) → O(N)） |
| FTS 索引重建 | 1.55 s | 1.57 s |
| `graph_get` 全量 | 23.5 ms（**被截断到 500 节点**） | **96 ms（2000 节点 / 3035 边，truncated=true）** |
| `graph_get` 分类过滤 / 2 跳聚焦 | 22.0 / 22.9 ms | 23.4 / 88.1 ms |
| `database.sqlite` / `.knowledge` | 6.7 / 10.8 MB | 7.2 / 11.8 MB |

结论：图谱查询满足 M3 验收口径（全量 96 ms < 1.5 s）；`links_rebuild` 已不再随笔记数平方增长。
首次采纳 3000 个外部文件约 28 s（逐篇写库 + 建索引），是「导入已有目录」的一次性成本。

### 首次导入 1 万篇：6.3 分钟 → 4 秒（完成）

**目标**：把「首次导入 1 万篇」从约 6.5 分钟压到 1 分钟以内。**结果：4.0 s（带文件监听 4.2 s）**，提速约 90×。

三个真实原因（前两个都是「按 UNINDEXED / 未复用索引做逐篇操作」导致的 O(N²)）：

| 编号 | 原因 | 修法 |
| --- | --- | --- |
| R1 | FTS5 的 `note_id` 是 **UNINDEXED** 列，`DELETE … WHERE note_id = ?` 每篇都要全表扫描索引 | 新增 `search_documents_map(note_id → row_id)`（迁移 006），删除改按 **rowid 主键**；rowid 由 FTS5 `last_insert_rowid()` 分配（**不能用 `MAX(row_id)+1`，那同样是全表扫描**） |
| R2 | `RelationService::rebuild` 每篇都重建一次标题索引（O(N²)） | 标题索引整轮只构建一次，批量复用 |
| R3 | 单篇采纳要 4–6 次独立事务提交（记录/标签/FTS/标记已索引/快照） | 采纳改为**按批事务**：读取解析在事务外完成，200 篇一个事务批量写入（记录 + 标签 + FTS + 标记已索引） |

实测（`BENCH_NOTES=10000`，同一台机器）：

| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| 扫描采纳（停掉监听，单趟） | 388.9 s | **3.96 s** |
| 扫描采纳（带文件监听） | 486–493 s | **4.16 s** |
| FTS 全量重建 | 23.5 s | **4.2 s** |
| 提取阶段 / 写入阶段 | — | 0.47 s / 0.47 s（1 万篇） |
| 检索延迟（含摘要高亮） | 平均 18.1 ms / p95 44.2 ms | 平均 18.2 ms / p95 44.2 ms |
| 独特术语 / 混合写法 / 中文短语 recall | 100% / 100% / 100% | 100% / 100% / 100% |

**升级影响**：迁移 006 会创建映射表并清空既有 FTS 索引（旧索引没有 rowid 映射）；
应用下次打开工作区时会检测「已索引 < 总数」并**自动重建一次**（实测 1 万篇约 4 秒）。

### 基准发现的两个问题：修复其一、其二定位到更深一层（V1.1.2 开发中）

**① 混合中英文写法召回 0% —— 已修复。**
根因：查询表达式把 `术语A7F3` 拆成「CJK 双字」AND「拉丁前缀」两个条件，
而索引侧（unicode61）把它当作**一个整 token**，两个条件必然同时落空。
修复：`build_fts_match` 先按空白切块，**混合块整体作为前缀短语**（`"术语a7f3"*`）；
纯中文仍是双字短语、纯英文仍是前缀，语义不变。新增单测覆盖四种写法。

实测（`BENCH_NOTES=10000`）：

| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| 混合写法 `术语XXXX` recall@5 | **0%** | **100%** |
| 纯英文 `termXXXX` recall@5 | 100% | 100% |
| 中文四字短语命中率 | 100% | 100% |
| 检索延迟（含摘要高亮） | 平均 18.1 ms / p95 44.2 ms | 平均 17.9 ms / p95 43.5 ms |

**② 首次采纳大目录耗时超线性 —— 已定位到采纳路径内部（下一轮批事务化）。**

已做的改动（保留）：采纳路径不再**逐篇**刷新链接与关系（每篇都会重建一次标题索引 → O(N²)），
改为「本轮真正要采纳的数量 > 50 时，整轮结束后统一重建一次」，监听批次同理。

但 1 万篇实测**没有改善**（306 s → 392 s → 400 s → 486 s，含机器负载波动），
说明主因不在链接索引重建，而在更深的两层：

1. **每篇笔记 4–6 次独立提交**（插入记录 / 建标签 / 写 FTS / 标记已索引各自一个事务），
   1 万篇 ≈ 5 万次事务提交；
2. **轮询式文件监听每 3 秒做一次全库扫描**：`scan_scope` 对每个文件都要读取 + 计算 sha256
   才能判断是否变化（1 万次读取 + 哈希），导入期间与采纳重叠，成倍放大耗时。

**已实施「mtime + size 短路」**（迁移 005：`notes.file_size` / `notes.file_mtime`）：
扫描与监听先比对快照，未变化的文件不再读取全文与计算 sha256；应用自身写入后会刷新快照。
这对**稳态扫描**（打开工作区、轮询监听）有效，但对「首次采纳新文件」无效——
因为新文件本来就没有快照可短路。

**对照实验（关键证据）**：用 `BENCH_STOP_WATCHER=1` 停掉文件监听，单独测采纳本身：

| 规模 | 停掉监听 | 单篇耗时 |
| --- | --- | --- |
| 2000 篇 | **14.2 s** | 7.1 ms |
| 10000 篇 | **388.9 s** | **38.9 ms** |

两者都是「单趟扫描」，说明**超线性发生在采纳路径内部**（不是监听叠加）。
按每篇分解：读取+解析+sha256 ≈ 1 ms、FTS 插入 ≈ 2.3 ms（1 万篇实测 FTS 全量重建 22.8 s）、
而 4–6 次独立事务提交（记录 / 标签 / FTS / 标记已索引 / 快照）在库增长后成为主要开销
（WAL 检查点随库体积变贵）。

**下一步（唯一正确的修法）**：采纳按批事务化——每 200 篇一个事务，
把「每篇 4–6 次提交」降到「每批 1 次」，同时显著减少 WAL 检查点次数。
需要把 `&Connection`/`&Transaction` 参数贯穿 `adopt_file` → `TagService` / `IndexService`，
避免在 `with_conn` 回调内再次 `with_conn`（现有实现的已知死锁点）。

### 中文分词：1 万笔记基准与决策（完成，结论：暂不引入）

基准脚本 `src-tauri/tests/search_bench.rs`，手动执行：
`BENCH_NOTES=10000 cargo test --offline --test search_bench -- --ignored --nocapture`

实测（macOS aarch64，本机，10000 篇 / 8 分类）：

| 项目 | 200 篇 | 10000 篇 |
| --- | --- | --- |
| 写入 Markdown | 18 ms | 484 ms |
| 扫描采纳（含建索引） | 0.30 s | **306.7 s（5.1 分钟）** |
| FTS 全量重建 | 69 ms | **24.5 s** |
| `database.sqlite` | 0.8 MB | **31.1 MB（约 3.2 KB/篇）** |
| `.knowledge` 合计 | 4.8 MB | 41.0 MB |
| 检索延迟（含摘要高亮） | 平均 0.7 ms / p95 1.7 ms | **平均 18.1 ms / p95 44.2 ms** |
| 中文四字短语命中率（“查询优化”） | 100% | **100%** |
| 纯英文 token recall@5 | 100% | **100%** |
| 混合写法「术语A7F3」recall@5 | 0% | **0%** |

**决策：暂不引入外部分词或预分词字段。** 依据：1 万篇下索引体积约 31 MB（含 FTS，可接受）、
交互检索 p95 44 ms、现有「单字 + 双字」策略对中文短语与纯英文 token 的召回均为 100%。
按 PLAN_V1.1 的约定（未达阈值不引入分词依赖），这一项到此结束。

基准同时暴露两个**与分词库无关**的真实问题，已记录待修：

1. **混合中英文写法召回为 0**：`术语A7F3`、`SQLite索引` 这类「中日韩 + 拉丁」无分隔字符串，
   现有查询构造（`core::text::build_fts_match`）无法命中（纯英文与纯中文都正常）。
   属查询表达式构造问题，不需要引入分词依赖；
2. **首次采纳大量文件耗时超线性**：3000 篇约 28 s，10000 篇 306.7 s（3.3 倍数据 → 11 倍耗时），
   FTS 重建同样从 1.5 s 涨到 24.5 s。原因是逐篇提交事务；后续应把「扫描采纳」改为分批事务。

### M2-1 编辑体验：图片粘贴 / 大纲 / ⌘P 快速切换（已完成）

- **图片与附件粘贴落盘**：编辑器里直接粘贴或拖入图片，文件写入
  `attachments/YYYY-MM/<时间戳>-<原名>-<短ID>.<扩展名>`（原名会做非法字符清洗），
  正文自动插入**相对当前笔记目录**的 `![](../attachments/…)` 链接；
  - 大小上限 20 MB，超过时提示改用「导入外部文件」；
  - 扩展名优先取原始文件名，其次由 MIME 推断，未知类型回落为 `.bin`；
  - 附件不进入 `notes` 表，也不会被当作笔记扫描；
  - 预览按需把工作区内相对图片读成 data URL 内联显示（单张预览上限 8 MB，
    外部链接与越界路径一律拒绝），因此粘贴后立刻能在预览里看到；
- **编辑器大纲**：工具栏「大纲」开关（编辑 / 分屏模式可用）在右侧列出 `#` 标题层级，
  按层级缩进，点击跳转到对应位置；忽略代码块中的 `#` 与没有空格的 `#`；
- **⌘/Ctrl + P 快速切换**：按标题模糊匹配（子串或按顺序的字符），↑↓ 选择、回车打开；
  与 ⌘K 全局搜索分工：⌘K 检索正文，⌘P 只用于「打开某一篇」；
- 新增命令 `attachment_save`、`attachment_read`（后者只读取**工作区内的相对路径**，
  用于预览内联；http/https/data/asset 与越界路径会被拒绝）；
- 浏览器预览模式（`pnpm dev`）对附件命令给出「请在桌面应用中使用图片粘贴」的明确提示；
- 测试：Rust 5 个附件集成测试（落盘路径与文件名、data URL 输入、空/超大/非法 Base64、读取与越界拒绝）
  + 前端 19 个单测（Markdown 代码区域与大纲解析、附件路径生成、标题模糊匹配、
  大纲面板、快速切换面板）。

### M2-2 双向链接体验：`[[` 补全与预览 chip（已完成）

- **`[[` 自动补全**：编辑器中输入 `[[` 即弹出笔记标题候选（子串匹配、前缀命中优先、最多 20 条），
  选中后自动补上 `]]`；补全列表由当前工作区的标题提供，`Esc`/失焦自动关闭；
- **预览 chip**：正文里的 `[[标题]]` 在预览中渲染为可点击 chip —
  - 已解析：品牌色 chip，点击跳转到目标笔记；
  - 未解析：琥珀色虚线 chip（带 `+` 图标），点击**按标题创建目标笔记并自动建立连接**后跳转；
  - 代码块与行内代码中的 `[[…]]` 不会被渲染成 chip（与解析规则一致）；
- 解析规则集中到 `src/lib/wikilink.ts`（Rust 端与浏览器预览后端共用同一套语义），
  避免三处实现漂移；
- 渲染方式：预览前把 `[[标题|别名]]` 预处理为 `[别名](#wikilink/<目标>)`，
  由 `a` 渲染器识别并换成 chip，因此**不需要**修改 Markdown 源文件；
- 测试：4 个解析/chip 链接往返测试、3 个预处理测试、4 个补全源测试、4 个预览 chip 测试，
  E2E 新增第 20 步（两个 chip 的文案与跳转）。

### M2-2 本地模板（已完成）

- 模板是工作区内的普通 Markdown 文件，位置 `.knowledge/templates/*.md`（新建工作区时会写入
  一个示例「会议记录」模板，可直接修改或删除）；
- 新建笔记对话框在检测到模板后显示「模板」下拉：选择后把**渲染结果填入初始内容**，

  （另接受 `{{标题}}`、`{{日期}}`、`{{时间}}`）；未知占位符原样保留，便于自定义；

### 修复

| 问题 | 根因与处理 |
| --- | --- |
| 分栏「拖不动 / 一拖就贴边」 | 把手传的是像素**增量**，却直接喂给期望**绝对值**的宽度设置，第一下就被夹到最小宽度；改为值语义 API（`value/min/max/onChange/scale`） |
| 分屏比例「过渡不自然，切模式后才正常」 | 分屏容器的 `ResizeObserver` 挂在 `useEffect([editorMode])`，首次进入笔记时容器尚未挂载，观察器永不建立，拖拽按 1px = 1 换算比例而瞬间贴边；改用回调 ref，并在宽度未知时不做换算 |
| 切换笔记回到预览模式 | 视图模式此前只在拖拽分栏时才顺带持久化；现在切换即写入设置，打开/切换笔记与重启都保持一致 |
| 状态栏 `invalid args 'input' for command 'settings_update'` | Retina 屏下 `clientX` 为小数（如 320.5），前端把小数写入整数像素字段导致后端反序列化失败；前端取整、比例保留三位小数，后端数值字段改为宽容解析（四舍五入） |
| 新建笔记无法导入外部文件 | 新增导入页签（见上） |
| 列表底部出现无说明的宽度滑块 | 移除滑块，改为列表与编辑器之间的拖拽把手；「清除筛选，查看全部笔记」仅在按分类/标签筛选时出现 |
| 首页/设置页右侧大片空白 | `<main>` 为 flex 容器而页面根节点缺少 `flex-1`，内容被压到内容宽度；已修正并在宽屏下改为两列布局 |
| 导入成功后停在结果页 | 成功后自动关闭对话框并打开第一篇导入的笔记；仅在全部失败时保留原因面板 |
| 文件名标题推断错误 | `file_stem_title` 未正确剥离 `YYYYMMDD-HHmmss-` 前缀、不识别 `.txt`；目录导入时根目录被隐藏文件规则误过滤 |
| Markdown 表格导出 Word 丢表头 | pulldown-cmark 的表头不经过 `TableRow`，已在 `TableHead` 结束时收行 |
