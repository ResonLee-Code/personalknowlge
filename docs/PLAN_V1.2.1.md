### 5.2 新增需求：研究助手（对话式深入调研 → 写入知识库）

用户目标（2026-10-10 提出）：**在应用内用对话让 AI 深入研究一个课题**——
自行查找资料、交叉验证，并在用户要求时把结果**同步进知识库**；
因为载体是知识库，来源的**权威性必须可验证、可疑处要显式警告**，并且要**保证时效**。

规格已写入 [AI_ARCHITECTURE_PLAN.md](./AI_ARCHITECTURE_PLAN.md) **§9**，要点：

| 维度 | 设计要点 |
| --- | --- |
| 能力定位 | 决策层的一个 capability（不是另一个聊天框），复用工具层与检索层；唯一新依赖是**联网工具** |
| 流程 | 立项 → 收集（本地优先，再外部）→ 交叉验证 → 汇总报告 → **用户确认后**写回 |
| 权威性 | 来源 A–E 五级（官方/标准/论文 → 论坛/AI 生成），写进 `source_reliability`；弱来源需两个独立来源一致；不可用来源只作线索并**给出警告块** |
| 时效性 | 每个来源记 `fetched_at` / `published_at` / `applicable_version`；报告顶部固定「资料截至 YYYY-MM-DD」；按领域给 `valid_until`，到期提醒复核；判「已被更新版本取代」标为可能过时 |
| 写回 | 默认落 Inbox、同标题不覆盖、写入前 diff、可回滚（复用 N1 元数据 / 子文档 / 版本历史） |
| 防幻觉 | 报告分「已验证 / 单一来源 / 模型推测」三段，推测段默认折叠；无引用的句子不进结论段 |
| 安全 | 联网是**独立闸门**（默认关闭）；抓取内容视为不可信输入（注入防护）；只存摘要 + 引用，不整篇复制 |
| 成本 | 子问题 ≤ 5 / 抓取页 ≤ 12 / ≤ 8 分钟，触顶即停并汇报 |
