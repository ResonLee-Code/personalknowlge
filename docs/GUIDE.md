## 1. 它是什么，适合谁

**一句话**：把笔记以 Markdown 文件存在你自己的目录里，用一套顺手的中文友好界面做分类、检索、
图谱、备份与研究的桌面应用。

三条设计原则（决定了它的很多行为）：

1. **数据自主**：正文是普通 `.md` 文件，你随时可以用别的工具打开、编辑、迁移；
   数据库（`.knowledge/database.sqlite`）是**派生数据**，删了能从 Markdown 重建。
2. **本地优先**：默认不联网、不接任何模型；检索走本地 FTS5；附件、备份、导出全在本机完成。
3. **AI 默认关闭、可解释**：联网是独立闸门（默认「仅本地」且首次使用要确认），
   决策/生成/AI 工具失败会自动降级并在报告里写明**实际用的是哪一档**。

**适合**：想把笔记真正留在自己硬盘上、又需要中文全文检索与结构化组织的人；
以及想在自己知识库上做"有据可查"的调研、并且**不能接受模型硬答**的人。
**不适合**：需要多端实时协作、云端同步与在线共享的人（这一版不做这些）。

## 2. 五分钟上手

### 2.1 安装

从 [v1.3.0 Release](https://github.com/ResonLee-Code/personalknowlge/releases/tag/v1.3.0) 下载对应平台产物，
先校验再安装（**强烈建议**，尤其在网络不稳时）：

```bash
shasum -a 256 -c SHA256SUMS-all.txt      # macOS；Linux 用 sha256sum -c
```

| 平台 | 第一次打开会发生什么 |
| --- | --- |
| macOS（arm64） | 应用是 **ad-hoc 签名**（没有 Apple 开发者证书、也没公证）。双击后会提示「**无法验证开发者**」：到 **系统设置 → 隐私与安全性**，在安全性一节点「**仍要打开**」，再确认一次即可，之后不再提示。<br>（如果你看到的是「**已损坏，无法打开**」，那是没走 ad-hoc 签名的旧构建——请用 V1.3.0 的包并在 Issue 里提一声。） |
| Windows（x64） | 未签名：SmartScreen 会拦一下 →「更多信息」→「仍要运行」。安装包外壳是 32 位 stub 属正常现象。 |
| Linux（x64） | `.deb` / `.rpm` 直接装；`.AppImage` 需要 `chmod +x`。系统需有 **WebKitGTK 4.1**（Ubuntu 22.04+ 一般自带）。 |

平台细节（静默安装、卸载、残留清理）见 [Windows 安装指南](./WINDOWS_INSTALL_GUIDE.md) 与
[Linux 安装指南](./LINUX_INSTALL_GUIDE.md)。

### 2.2 创建第一个知识库

首次启动是欢迎页：

1. **知识库名称**：显示名（例如"我的知识库"）；
2. **保存目录（绝对路径）**：你想把它放在哪，例如 `/Users/you/Documents/MyKnowledge`；
   目录不存在会被创建，**已存在且是空目录也可以**（就地初始化）；
3. 点「**创建知识库**」。已有目录想直接接管？用「**打开已有目录**」。

创建完成后，目录里会长出 `.knowledge/`（数据库、配置、备份、模板、历史、日志）、
`00_Inbox/`、`attachments/` 等；右侧「最近打开」会记住它，下次一键进入。

### 2.3 写下第一篇笔记

- 侧边栏「**新建笔记**」或 `⌘N`：对话框有三个入口——**手动创建** / **导入外部文件** / **从网页剪藏**；
- 输入标题（必填），可选分类、标签、模板与初始内容 → 点「创建笔记」；
- 编辑器里直接写 Markdown：`#` 标题、`-` 列表、`**加粗**`、表格、代码块都支持；
- 输入 `[[` 会弹出笔记标题补全，选中即插入双向链接；
- 粘图片会自动存进 `attachments/YYYY-MM/` 并插入相对路径；
- 保存是自动的（默认约 1 秒防抖）；`⌘S` 立即落盘，`⌘E` 把焦点交给编辑器。

### 2.4 找回来

- `⌘K`：全局搜索（标题/正文/标签，带摘要高亮）；
- `⌘P`：按标题快速切换（模糊匹配，↑↓ 选择，回车打开）；
- `/search` 页面：带上过滤器（分类 / 标签 / 收藏 / 时间）与排序。

到这里，日常 80% 的用法你已经会了。下面按需深入。

## 3. 界面地图与快捷键

```text
TopBar：全局搜索(⌘K) · 保存状态 · 主题 · 设置
侧边栏：首页 / 全部笔记 / Inbox / 收藏 / 知识图谱 / 研究助手 / 附件 / 目录管理 / 分类 / 标签 / 回收站 / 设置
中栏：笔记列表（标题筛选 · 排序 · 多选 · 条目菜单）⇄ 大纲（点中栏头部的「大纲」开关切换）
右栏：编辑器 / 预览（工具栏 · 关系面板 · 反向链接）
StatusBar：索引状态 · 统计 · 运行模式
```

侧边栏收起 / 展开的开关在侧边栏**底部那一行**——收起后它也停在同一个高度，不会跳位置；
收起后这一栏变成**图标栏**（对 Codex 桌面端）：导航项都在，选中项高亮、鼠标移上去显示名字，
点图标就能直接切页面，不用先展开。右上角那个设置齿轮是唯一的设置入口；
分类、标签两个区块点标题可以折叠。
侧边栏宽度、列表宽度、编辑器分屏比例**都可以拖**（双击复位、方向键微调），并且**随工作区记住**；
窗口的尺寸与位置也会记住（跨屏拔掉外接屏时只恢复尺寸，位置交给系统，避免开出点不到的窗口）。

| 快捷键 | 作用 |
| --- | --- |
| `⌘/Ctrl + N` | 新建笔记 |
| `⌘/Ctrl + K` | 全局搜索 |
| `⌘/Ctrl + P` | 快速切换笔记 |
| `⌘/Ctrl + S` | 立即保存 |
| `⌘/Ctrl + E` | 聚焦编辑器 |
| `⌘/Ctrl + W` | 关闭当前笔记 |
| `Delete` | 删除选中的笔记（进回收站） |

## 4. 笔记与编辑

### 4.1 编辑器三种视图

工具栏「**编辑 / 分屏 / 预览**」一键切换并记住；分屏比例可拖（0.3–0.7）。

**大纲默认不在正文右边**（V1.3.0 起的布局调整）：它和笔记列表**共用中栏**——
这一栏平时是笔记列表，点中栏头部右侧的「**大纲**」开关（在篇数右边）就换成大纲
（横向不多占一列，正文因此更宽），栏头「**〈〈 返回列表**」切回列表。
没有选中笔记时这个开关是灰的（那会儿没有大纲可看）。栏头右上「**钉在正文右侧**」可以把它挪到
正文右边（宽屏更顺手），右边的大纲里则有「**改到笔记列表那一栏**」挪回来。
钉在右侧时仍是原来的三态：**固定** → 「收起大纲」变**贴边 mini**（鼠标移上悬浮展开）→
面板内「钉住大纲」回到固定，再点中栏头部那个开关即**隐藏**。正文没有标题时大纲会提示用 `#` 开头。

两个开关在 **设置 → 编辑器**：「**大纲位置**」（与笔记列表共用一栏 / 钉在正文右侧）与
「**选中笔记后自动显示大纲**」（默认关，打开后每次选中笔记都直接看结构；默认关是因为
连着点几篇浏览时每次都被切走会打断节奏）。**位置**随工作区记住；而"这一栏此刻显示列表还是大纲"
不落库——应用重开后回到列表，运行期间（连着看几篇笔记时）保持你选的那个。

### 4.2 双向链接与反向链接

- 写 `[[标题]]` 建立链接（`[[` 触发标题补全）；预览里链接是可点的 chip；
- 编辑器下方「**反向链接**」显示"谁引用了我"，点击跳转；
- 「**未解析链接**」卡片列出指向不存在笔记的链接，可**一键创建**那篇笔记并建立链接；
- 关系更强的表达用「**关系**」面板：支持类型化关系（派生 / 取代 / 相关…）与说明。

### 4.3 子文档与大纲

在列表里**拖拽**一条笔记到另一条上 = 成为它的子文档；拖到条目之间 = 同层排序（切换成"自定义顺序"）；
层级写进 frontmatter 的 `parent` / `order`，所以**外部编辑也不会丢**。支持置顶（任何排序下都在该层最前）。

### 4.4 模板、历史版本、导出

- **模板**：「更多操作 → 另存为模板…」把当前笔记存成模板（写入 `.knowledge/templates`），
  新建笔记时可选；模板支持 `{{title}}` `{{date}}` `{{time}}` `{{datetime}}` `{{weekday}}` 占位符。
- **版本历史**：保存前自动留档（60 秒节流、每篇最多 50 份）；「更多操作 → 历史版本…」可
  **命名版本**、**任意两版对比**（逐行增删）、**还原正文**（只回滚正文，标题/标签/分类保持现状）。
- **导出**：Markdown（原样含 frontmatter）/ HTML（自包含单文件）/ Word `.docx` / PDF（走打印视图另存）。

### 4.5 编辑时可能遇到的三种"意外"

| 现象 | 含义 | 怎么办 |
| --- | --- | --- |
| 头部显示「**保存失败：文件已被其他程序修改…**」 | 你在外部改过这个文件（或用 `cp` 把旧版本写回），编辑器手里的基准已经过期——**这是冲突保护在工作**，不是缺陷 | 点开「详情」看清楚 → 选「重新加载」（以磁盘为准）或「覆盖保存」（以编辑器为准） |
| 显示「**已保存（检索索引待重建）**」 | 正文已写盘，但索引更新失败，检索里暂时搜不到这篇 | 「设置 → 索引与数据 → 重建」，或重启应用 |
| 文件被外部删除/移走 | 笔记被标为「**缺失**」，而不是变成空正文 | 把文件放回原位后重新扫描即自动恢复；或到「目录管理」处理 |

## 5. 组织：分类、标签、收藏、回收站

- **分类**：`/categories` 管理分类树（可嵌套）。分类**对应目录**，重命名分类会同步目录与文件路径；
  删除分类时选策略：**移到 Inbox** / **移到父分类** / **取消分类**（都不会删笔记）。
- **标签**：`/tags` 创建/重命名/删除；一篇可挂多个标签；标签名**大小写不敏感唯一**。
- **收藏**：`/favorites`，或在列表条目菜单里切换。
- **回收站**：删除 = 移入 `.trash/`（保留原相对路径）→ 可**恢复**或**永久删除**。
  恢复时若原路径已被别的文件占用，笔记会**换一个安全路径**恢复，那个文件原封不动。
- **目录管理**：`/manage` 是跨状态宽表（活跃 / 回收站 / 缺失），支持搜索、「不在目录中」筛选、
  批量移动 / 打标签 / 删除 / 复制。

## 6. 检索：搜索、图谱、附件

### 6.1 搜索行为

- 索引是 SQLite **FTS5**；中文按「单字 + 双字」扩展，英文按前缀匹配，标题命中优先；
- 过滤：分类、标签、收藏、时间；排序：相关度 / 更新时间；
- 结果带**摘要高亮**；索引状态在「设置 → 索引与数据」，可手动「重建」或「扫描」外部改动；
- 规模实测（本机）：**1 万篇**检索平均 ~20 ms、p95 ~48 ms、召回 100%。

### 6.2 知识图谱（`/graph`）

节点 = 笔记，边 = 双向链接。可分类着色 / 按度数定大小、按分类与标签过滤、只看孤立节点、
1–2 跳聚焦，缩放平移、拖拽固定位置，双击节点打开笔记。
**大库会抽样**：每个分类都保留代表，并把高连接节点的邻居一起带进来。

### 6.3 附件（`/attachments`）

按 `YYYY-MM` 分组列出附件、体积、修改时间与**引用它的笔记**。
「**只看未引用（N 个 · X MB）**」把没人引用的筛出来，方便清理。

**"未引用"的判定口径**（写在 [API 契约](./API_CONTRACT.md)，改口径会同步改文档）：

| 正文里的写法 | 算引用吗 |
| --- | --- |
| `![图](../attachments/2026-10/a.png)`（应用自己写的相对路径） | ✅ |
| `![[attachments/2026-10/a.png]]` | ✅ |
| `![[20261014-…-a.png]]`（只写**完整文件名**） | ✅ |
| `![[图.png]]`（你最初的原始文件名） | ❌ **悬空引用**：附件落盘时会被重命名，这条链接本来就打不开 |

删除附件是逐条确认的动作；引用中的附件删除后引用会失效，确认框会列出引用它的笔记。

## 7. 数据与安全：备份、恢复、外部编辑

### 7.1 目录长什么样

```text
MyKnowledge/
├── .knowledge/
│   ├── database.sqlite      # 元数据 + FTS5 索引 + 设置 + 决策缓存 + chunk 向量
│   ├── config.json          # 工作区配置
│   ├── backups/             # 备份包（zip）
│   ├── templates/           # 本地模板
│   ├── history/<笔记 id>/    # 版本历史快照
│   ├── research/            # 研究助手会话（可丢弃）
│   ├── logs/app.log         # 运行日志（失败原因与界面提示同一份）
│   └── logs/ai-audit.jsonl  # AI 行为审计（不含正文）
├── .trash/                  # 回收站
├── 00_Inbox/ 01_技术/ … 
└── attachments/
```

### 7.2 备份 / 校验 / 恢复

「设置 → 备份与导出」：

1. **立即备份** → 生成 `KnowledgeBackup_<时间戳>.zip`（含数据库、配置、全部笔记、附件、历史、模板、清单文件）；
2. **校验** → 就地给出逐项结果（✓ 清单文件存在 / ✓ Markdown 数量一致 / ✓ 附件数量一致 / ✓ 版本历史与模板数量一致）；
3. **恢复** → 选一个**空目录**，得到一份完整可用的知识库；
4. **导出 Markdown** → 把全部笔记导出为普通目录（适合交接或迁移）。

> 备份包里的中文文件名带 UTF-8 标志位，跨平台解压不会乱码。

### 7.3 外部编辑与冲突

应用**监听工作区目录**（原生事件 + 轮询兜底）：外部新增/修改的文件会被自动采纳并重建索引，
被移走的会标为「缺失」，自己写入产生的回声会被忽略。
如果你在编辑器打开着这篇笔记时从外部改了它，下一次保存会被**冲突保护**拦下（见 §4.5）——
它宁可让你选，也不会静默覆盖任何一方的改动。

### 7.4 数据可恢复到什么程度

| 丢了什么 | 怎么办 |
| --- | --- |
| `.knowledge/database.sqlite` | 重新打开工作区会自动重建；检索索引、缓存、向量都会重建（这些是派生数据） |
| 单篇笔记的历史版本 | 在 `.knowledge/history/<笔记 id>/`，也可以从备份包恢复 |
| 整台机器 | 用备份 zip 恢复；或直接把工作区目录拷到新机器打开 |
| 误删笔记 | 先看 `.trash/`；已永久删除的只能靠备份 |

## 8. AI 能力：默认关闭，开哪档用哪档

> **默认口径**：AI 总开关 **关**、联网档位 **仅本地**、抓取网页正文 **关**。
> 也就是说，装完不配置，它就是一个纯本地应用——不会发任何请求。

### 8.1 四道闸门（想外发要过几关）

| 闸门 | 默认 | 说明 |
| --- | --- | --- |
| AI 总开关 | 关 | 关闭时所有 AI 能力直接拒绝（`AI_DISABLED`） |
| 联网档位 | 仅本地 | 切到「允许联网」仍需**每次确认**；换地址或模型名后授权作废 |
| 逐次外发确认（可选） | 关 | 打开后**每次外发前**都会给你看「将要发送的片段 + 目标主机」 |
| 域名黑白名单 | 空 | 黑名单**强制丢弃**（优先级高于白名单），被丢弃的结果在报告里可见 |

所有外发行为都写进 `.knowledge/logs/ai-audit.jsonl`（时间/能力/是否外发/结果/耗时，**不含正文**）。

### 8.2 决策模型档（可选）

「设置 → AI → 决策模型」可在两档之间切换：

- **规则档**（默认）：离线、零成本、永远可用，按关键词/极性词打分；
- **System One 档**：填地址 + 模型名 + API Key（Perplexity Decisions 与 Jev 同协议，一份适配器覆盖两家），
  Key **只写不读**、独立授权、可随时清除。

配好并授权后，**决策档排在候选链最前**；失败自动降级到规则档，报告里写明实际用的哪一档。
想先看数据：点「**决策探针**」用**我们自己的中文题**跑出准确率、自洽性、两次一致性、矛盾判别、
延迟与估算成本；题目含 **100 道可判分题**，给出 ECE / Brier / 分箱与**折外** ECE，
以及**规则档 vs 决策档的 A/B 打分对比**。

> 实测口径（V1.3.0）：材料内题 **40/40、ECE 0.0159**；材料外题偏"说没有"（平均陈述 0.376）——
> 所以**不要**把材料外的低分读成"确定无关"，它更像"它不认识这东西"。

### 8.3 研究助手（`/research`）五步

1. **立项**：填课题（3–5 个子问题；过于宽泛会被要求补充范围）。
   **同时会做查询扩展**（课题 → 括号短语 / 连接词切分 / 拉丁词，≤6 条，规则化、离线），
   检索按这组查询逐条跑再按笔记去重；
2. **收集**：本地 FTS5（开了联网档位可同时检索外部，来源按域名策略过滤与分级）；
3. **验证**：同一子问题 ≥2 个**独立**来源才算交叉验证；来源矛盾时**并列呈现、不替你选边**；
4. **汇总**：固定六段报告（结论先行 / 关键事实 / 争议与不确定性 / 与本地知识库的关系 / 待验证清单 / 参考来源），
   每条结论带引用与置信度；顶部固定「资料截至 YYYY-MM-DD」；
5. **写入提案**：默认落 Inbox、同标题**不覆盖**、写前给你看 diff、写入后可在版本历史里回滚。

**证据不足时它会明说「不够」**：报告顶部、警告块与结论段三处同时告诉你缺口在哪
（哪些子问题没材料、有没有 ≥2 个独立来源、材料是否太薄/太弱/可能过时），并给出怎么补。
这道判断的意义：它默认的失败方式原本是"材料不够还答得像模像样"，现在改成"**不给结论**"。

### 8.4 向量检索（可选增强）

「设置 → AI → 向量检索」：填**嵌入模型名**（复用在线模型地址与 Key，需**一次性确认**），
确认后增量构建；向量只存派生数据、可一键重建、不进备份。
开启后检索会多一路 `vector` 通道参与 **RRF 融合**——**不可用时自动退回纯 BM25，检索永远可用**。

### 8.5 本地 / 在线模型与生成

- **本地模型（Ollama）**：只允许连本机地址，默认关闭；「低配机型预设」一键填 `qwen2.5:3b` / `qwen2.5:7b`；
- **在线模型（OpenAI 兼容）**：填地址 / 模型名 / Key，首次授权后可用；
- **模型自检**：一键看「写报告」现在会用哪一档、以及为什么（只读，不联系在线端点）；
- 优先级：**在线（已授权）→ 本地 → 模板**；任何一档不可用都自动降级，并把**实际 provider** 写进报告；
  报告里"是谁写的"与实际生效的档位一致（模板生成会明确标注「未接入模型」）。

## 10. 排错与常见问题

| 现象 | 原因与处理 |
| --- | --- |
| macOS 首次打开提示「无法验证开发者」 | 正常：本版是 ad-hoc 签名。到 **系统设置 → 隐私与安全性 → 仍要打开** 放行一次 |
| macOS 提示「已损坏，无法打开」 | 说明这个包**没有走 ad-hoc 签名**（旧构建）。请用 V1.3.0 的 Release 包；若 V1.3.0 仍出现，请报 Issue |
| Windows 安装/运行被 SmartScreen 拦 | 未签名：更多信息 → 仍要运行；安装包外壳 32 位属正常 |
| Linux 启动报缺库 | 装 WebKitGTK 4.1 与 GTK3（包名见 [Linux 指南](./LINUX_INSTALL_GUIDE.md)） |
| 保存失败，提示"文件已被其他程序修改" | 冲突保护（见 §4.5）：点「详情」看清原因，再选重新加载或覆盖保存 |
| 检索搜不到刚写的笔记 | 头部「已保存（检索索引待重建）」= 索引没跟上：设置里重建索引，或重启应用 |
| 笔记显示「缺失」 | 文件被移走/改名了：放回原位再「重新扫描」，或到 `/manage` 处理 |
| 大库打开慢 | 首次扫描与建索引是一次性成本；3 万篇图谱全量查询实测 ~0.9 s。索引/缓存在 `.knowledge/` 里，可重建 |
| 想重置全部设置 | 关掉应用，删掉工作区里的 `.knowledge/database.sqlite`（**会丢设置与版本历史索引**，正文不受影响；建议先备份） |
| 想彻底卸载 | 删除应用即可；**工作区目录是你的数据，不会被删**。应用数据（`~/Library/Application Support/PersonalKnowledgeOS`）与偏好设置需手动删除 |
| 报障要带什么 | 时间点 + 界面上那段**失败详情**（点「详情」可一键复制）+ `.knowledge/logs/app.log` 对应时间的行 |

# 本地开发

# 发布前守护（改检索/索引/图谱后尤其别跳过）
