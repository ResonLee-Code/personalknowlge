# V2 Ask 真实 DeepSeek 50 题评测

## 范围

- 日期：2026-10-23
- 模型：`deepseek-flash`
- 端点：`https://api.deepseek.com`
- 入口：应用真实 `AskService`，不是直接拼接聊天请求
- 样本：`src-tauri/tests/ask_eval_flow.rs` 的 50 条唯一事实题
- 每题的黄金来源：唯一笔记、唯一事实词和可引用原文块

该评测走完整检索、引用编号解析、在线模型生成、引用守卫和降级链。Key 只从应用数据目录
临时注入测试进程，不写入命令输出、测试报告或工作区。

## 修复前

最差一轮观测：

| 指标 | 结果 |
| --- | ---: |
| 在线答案被接受 | 50 / 50 |
| 最终交付含正确来源 | 50 / 50 |
| 引用总数 | 53 |
| 支持唯一事实的引用 | 50 |
| 聚合引用精确率 | **94.34%** |
| 所有引用都正确的题 | 47 / 50 |
| 耗时 | 112.2 s |

失败不是“缺引用”或“错来源替代正确来源”，而是模型在 3 个答案里额外引用了检索到但未
用于当前结论的材料：两处引用了 `ZIP 备份校验` 笔记，一处引用了欢迎笔记。按验收门槛
< 5% 误引，该轮 94.34% 不达标。

## 修复

Ask 生成契约增加一条明确约束：

> 每个编号都必须直接支撑紧邻的事实，不得引用仅出现于材料列表但与本条结论无关的来源。

没有放宽引用守卫，也没有把额外引用从统计中删掉；在线回答仍须通过原有编号解析，否则整份
回答丢弃并降级。

## 修复后

连续两轮完整 50 题：

| 轮次 | 在线接受 | 正确来源题 | 全引用正确题 | 引用支持 | 精确率 | 精确复现事实词 | 耗时 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 50 / 50 | 50 / 50 | 50 / 50 | 50 / 50 | **100.00%** | 49 / 50 | 110.2 s |
| 2 | 50 / 50 | 50 / 50 | 50 / 50 | 50 / 50 | **100.00%** | 49 / 50 | 111.3 s |

两轮均有 1 题用同义改写回答，未逐字复现黄金事实词；其引用的原文块包含该事实，因此不是
引用错误。该现象也说明自动字符串匹配不能替代语义级人工复核。

## 可确认与仍待人工

可确认：

- 50 条问题均返回在线答案，没有触发模板降级；
- 每条最终答案都包含指向唯一黄金来源的有效引用；
- 两轮引用精确率均为 100%，满足“引用精确率 ≥ 95%”；
- 引用编号不存在时可整份拒绝的自动守卫保持通过。

仍待人工：

- 逐题阅读问题、答案与引用，确认答案中的每个断言确实由引用原文支撑；
- 统计无依据断言率并确认 `< 5%`；
- 对 50 条问题、黄金答案和可引用段落签字；
- 使用用户真实知识库而非合成唯一事实夹具做语义质量抽检。

## 复现

```bash
cred_file="$HOME/Library/Application Support/PersonalKnowledgeOS/ai-credentials.json"
PKOS_LIVE_REMOTE_KEY="$(jq -er '.remoteModelApiKey' "$cred_file")" \
  cargo test --offline --manifest-path src-tauri/Cargo.toml \
  --test ask_eval_flow live_deepseek_fifty_labelled_questions \
  -- --ignored --nocapture
```

单组题诊断可额外设置：

```bash
PKOS_LIVE_CASE_FILTER='版本历史快照'
```

该变量只过滤问题文本，不改变模型、检索或引用校验。
