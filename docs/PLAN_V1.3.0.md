**落地纪律（每条任务都按这个走，写在这里免得散落）**

1. **先取证再改**：开工前把现状用命令/读码确认一遍，把结论写进任务卡（上面这张表就是模板）；
2. **先写能失败的测试**：新能力先写复现/守卫测试并看到它红，再改代码；修完必须能看到它绿；
3. **反向验证**：涉及安全 / 数据 / 权限的守卫，必须故意注入漂移看到测试失败（本轮 3 个 P0 都这么做的）；
4. **文档同步**：CHANGELOG（用户可见变化）+ 受影响的 `docs/*.md` + 验收表；`pnpm test` 里的文档守卫会拦你；
5. **收口口径**：全量回归绿（前端 + Rust + E2E）才算完成；**不许把「没验」写成「通过」**；
6. **真机验收**：涉及界面的项，用 E1 的脚本跑一遍并留截图；脚本覆盖不到的（安装、Gatekeeper）单独列"人工待办"。
