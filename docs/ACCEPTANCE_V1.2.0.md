### ⬜ 未能自动化（3 类原因）

| 项目 | 原因 | 建议 |
| --- | --- | --- |
| 编辑器内输入、`[[` 补全弹窗、自动保存「已保存」（D4/D6 部分） | CodeMirror 的 contenteditable **不接受辅助功能层的合成按键**（普通输入框/下拉可自动化，编辑器不行） | 人工：在编辑器中输入 `[[`，确认补全弹窗与「已保存」 |
| 来源与时效的下拉与日期（D8 部分） | 对话框与字段均已验证存在且可用，但 **macOS 原生下拉/日期控件无法通过 AX 改值**（多次尝试未生效） | 人工：设置来源类型=官方文档、可靠性=★★★★★、有效期=昨天，确认元信息栏出现来源标签与「可能已过期」 |
| 导入（D11/D12）、单篇导出（D13）、备份恢复（D14） | 需要**系统文件打开/保存对话框**；本轮未做（导出/备份的核心逻辑已有 Rust 集成测试 `export_flow` / `workspace_flow` 覆盖） | 人工：走一次 Obsidian/Notion 导入与 md/docx/pdf 导出 |

### 🐞 本轮发现的一个 UI 缺陷（建议修复）

**切换知识库后「知识图谱」页不会自动刷新**：切回真实库后图谱仍显示上一个库的节点数
（3 节点），点击「重新查询」才变为当前库的 2 节点。建议在 `/graph` 页监听工作区切换/`notes://changed` 后自动重新查询。

> 其余页面（笔记列表、附件页、状态栏）在切换工作库后都会自动刷新，仅图谱页有此问题。

## F. 已知限制（本版）

1. 未做代码签名与公证（macOS 需右键打开，Windows 需放行 SmartScreen）；
2. Windows 安装包为交叉编译产物，未做真机验收；
3. 知识图谱在超过 2000 节点 / 5000 边时按连接度截断并提示筛选；
4. 中文分词策略经 1 万篇基准验证（体积/延迟/召回均达标），本版**不引入外部分词依赖**；
5. 第二代 AI 能力仅有接口骨架（`DecisionModel` / `Retriever` / `GenerativeModel`），不含模型调用。
