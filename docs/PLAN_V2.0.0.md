# PLAN V2.0.0 —— 本地知识助手（Ask / Organize / Connect）

> 状态：**规划稿**（2026-10-20）。V1.3.6 是当前发布版；本文件只定义 V2.0.0 的范围与验收口径，
> 不代表已排期或已承诺日历时间。

## 1. 定位

V1.x 解决的是“**记得住、找得到、研究得动**”：本地 Markdown、FTS5、双链、图谱、研究助手、
可选的在线/本地模型。V2.0.0 要解决的是“**问得清、理得顺、连得上、复用得了**”：

- 回答必须**带引用**，能跳回原文的具体段落；
- 整理（摘要 / 标签 / 关联）必须**先建议、后写入**，可撤销；
- 连接必须是**可解释的**（为什么这两篇有关），不是黑盒推荐；
- 所有 AI 能力继续遵守现有隐私闸门：默认关闭、逐次授权、可降级、可审计。

一句话：**把知识库从“仓库”变成“可追问、可维护的助手”**。

## 2. 版本主题与优先级

| 主题 | 优先级 | 一句话 |
| --- | --- | --- |
| Ask：引用式问答 | **P0** | 对当前笔记 / 分类 / 全库提问，答案逐条给来源 |
| Organize：摘要 / 标签 / 关联建议 | **P0** | 批量整理，但先进入“待确认队列” |
| Research 2.0：多入口、可重跑 | **P0** | 从选中文字 / 命令面板 / 对话发起研究 |
| Platform 2.0：签名 / 更新 / Windows 真机 | **P0（发布门槛）** | 可信安装与升级 |
| Graph 2.0：语义连接 | **P1** | 语义近邻、重复检测、桥梁笔记 |
| Sync 2.0：可选加密同步 | **P1** | 用户自己的 WebDAV/S3，端到端加密 |
| Scale 2.0：10 万篇 | **P1** | 增量索引、后台任务、内存上限 |
| Writing：写作助手 | **P2** | 大纲 / 续写 / 改写，带引用与 diff |

> P0 是 V2.0.0 的发布门槛；P1 允许拆到 V2.0.x，但必须在发布说明里明确；
> P2 默认不阻塞 V2.0.0。

## 3. 功能项

### 3.1 Ask：引用式问答（P0）

**用户故事**：我在写一篇笔记，想问“之前关于 SQLite FTS5 的结论有哪些？”，
得到的每一条结论都能点回来源段落，而不是一段无法核对的漂亮话。

范围：

- 入口：右侧「问知识库」面板、命令面板 `AI: 问…`、选中文字右键「就这段提问」；
- 作用域：当前笔记 / 当前分类 / 当前标签 / 全库；
- 回答结构：结论 → 逐条引用（笔记标题 + 段落锚点 + 摘要片段）→ 证据不足时明确说“不足”；
- 多轮追问：保留会话上下文，但每轮都重新检索，不把上一轮答案当事实；
- 把答案存为笔记：写入前预览，自动带 `sources:` 与 `[[链接]]`；
- 只读优先：问答本身不写库；写回必须二次确认。

技术要点：

- 引用解析器：模型只允许引用检索结果里的 `chunk_id`；服务端把 `chunk_id` 映射到
  `note_id + block_offset + snippet`，模型编造的 id 直接判为“无依据”；
- 证据充分性沿用 `evidence.rs` 的六类缺口；不足时走“结论 + 缺口 + 建议补充”模板；
- 模型路由：在线（已授权）→ 可选本地 → 模板降级；每次请求显示实际通道；
- 预算：单次问答 token/费用上限，超限先提示。

验收：

- 50 条标注问答集：**引用可解析率 100%**；**引用精确率 ≥ 95%**；无依据断言率 < 5%；
- 20 条“库里没有”的问题：100% 回答“证据不足”，不编造来源；
- 从引用点击能跳到正确笔记与段落（自动化断言）；
- 未授权时 0 次外发（审计日志 + 网络 mock 双重验证）。

### 3.2 Organize：摘要 / 标签 / 关联建议（P0）

**用户故事**：我有 200 篇收件箱笔记，想让 AI 帮我摘要、打标签、找关联，
但不想让它悄悄改我的文件。

范围：

- 单篇 / 多选 / 当前分类的摘要；
- 标签建议（复用已有标签优先，新标签需确认）；
- 关联建议（普通链接 / 类型化关系，附“为什么”的一句话）；
- 重复 / 近重复检测（标题、正文片段、语义向量三路投票）；
- **待确认队列**：接受 / 拒绝 / 批量接受；每条显示 diff；接受后可一键撤销；
- 后台任务：进度、暂停、取消、失败重试；关窗不丢任务状态。

技术要点：

- 所有写操作走现有 `note_update` / `note_set_tags` 等命令，禁止直接改文件；
- 建议结果落 SQLite（`ai_suggestions` 表），带 `model / prompt_version / evidence`；
- 批量任务用持久化 job 队列；同一笔记同一类建议只保留最新一条；
- 接受前做冲突检查（文件在建议生成后被外部修改 → 要求重新生成）。

验收：

- 100 篇批量任务可暂停/恢复/取消；中途杀进程后重启能继续；
- 标签精确率 ≥ 80%（200 条人工标注）；关联建议接受率 ≥ 60%；
- 拒绝/撤销后文件字节级恢复；外部修改冲突 100% 被拦截；
- 任何建议在未点击“接受”前，工作区文件不变（自动化断言）。

### 3.3 Research 2.0：多入口、可重跑（P0）

范围：

- 三个新入口：命令面板、选中文字、Ask 对话里的「深入调研」；
- 研究计划可编辑（子问题、时间窗、来源类型、语言）；
- 计划可保存为模板；同一课题可**重跑**，对比上次来源与结论变化；
- 来源新鲜度：记录 `fetched_at / published_at / applicable_version`，过期来源标黄；
- 报告写回：生成笔记 + 来源清单 + 与研究课题的双链；
- 失败可恢复：采集中断后从已完成来源继续。

验收：

- 三个入口都能发起同一套研究流程；
- 同一课题重跑能列出“新增 / 消失 / 结论变化”的来源；
- 单来源结论 100% 标记“未交叉验证”；证据不足 100% 不给结论；
- 写回前必须确认；取消后不产生半成品笔记。

### 3.4 Platform 2.0：可信安装与升级（P0，发布门槛）

- Windows 真机：安装、升级、卸载、便携版、路径/中文/权限；至少 1 台真实设备；
- Linux 真机：Ubuntu 22.04 / 24.04 的 deb 安装与 AppImage 运行；
- macOS：Developer ID 签名 + 公证；首次打开不再需要“仍要打开”；
- 自动更新：Tauri updater / Sparkle 二选一，签名校验，失败可回滚；
- 诊断：崩溃日志本地保存，默认不上传；用户主动导出。

验收：

- 干净机器安装 → 升级 → 卸载，知识库与应用数据不受损；
- 更新包签名校验失败时拒绝安装并保留旧版；
- Windows / Linux 真机各至少 1 台，报告进 `docs/acceptance/`。

### 3.5 Graph 2.0：语义连接（P1）

- 语义近邻（“和这篇最像的 10 篇”），显示相似原因（共同实体 / 引用 / 主题）；
- 近重复聚类（同主题多版本），支持合并预览；
- 孤儿笔记、桥梁笔记、孤岛分类；
- 聚类摘要（可选，写入前确认）；
- 10 万节点降采样与增量更新。

验收：

- 200 对人工标注：近邻 precision@10 ≥ 80%；
- 每条边可展开“为什么连”（至少一个证据）；
- 3 万节点全量 < 1.5s，10 万节点首屏 < 3s（降采样）。

### 3.6 Sync 2.0：可选加密同步（P1）

- 只支持用户自己的 WebDAV / S3 兼容存储；不提供厂商云；
- 端到端加密（笔记正文、附件、索引可选）；
- 离线队列、冲突三方合并、冲突 UI、历史版本；
- 同步前 dry-run，显示将上传/下载/冲突的文件数。

验收：

- 两台设备模拟：新增 / 修改 / 删除 / 冲突四类场景；
- 冲突不丢数据，必须人工选择或三方合并；
- 服务端只有密文；关闭同步后本地功能不受影响。

### 3.7 Scale 2.0：10 万篇（P1）

- 增量索引 / 后台重建；索引分片；内存上限；
- 搜索结果分页与虚拟列表；图谱降采样；
- 启动 < 2s（10 万篇，SSD）。

验收：10 万篇基准：检索 p95 < 200ms、recall@5 100%、启动 < 2s、内存 < 1.5GB。

### 3.8 Writing：写作助手（P2）

- 大纲生成、续写、改写、缩短/扩写；
- 每个生成段落可插入引用；
- diff 预览，逐段接受；不静默改写；
- 与 Ask 共用引用解析器与预算控制。

## 4. 非目标（V2.0.0 不做）

- 实时多人协作 / 评论 / 权限体系（留给 V3.x）；
- 官方托管云与账号体系；
- 移动端原生 App；
- 插件市场 / 第三方脚本沙箱；
- 自动替用户做“重要决定”的 agent（研究助手仍是“建议 + 人工确认”）。

## 6. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 模型编造引用 | 只允许引用检索返回的 `chunk_id`；解析失败即判无依据；评测集守门 |
| 成本 / 延迟失控 | 路由 + 缓存 + 单次预算 + 批量任务限流；界面显示实际通道与耗时 |
| 静默写坏笔记 | 建议队列 + diff + 撤销 + 外部修改冲突检查 |
| 同步冲突丢数据 | 默认 dry-run；三方合并；冲突不自动覆盖；同步前备份 |
| 平台签名成本 | 提前申请 Developer ID / Windows 证书；签名与更新作为发布门槛 |
| 10 万篇性能回退 | 先建基准再写功能；CI 跑 1 万 / 3 万档，发布前跑 10 万档 |

## 7. 发布验收（V2.0.0 出口）

1. P0 功能全部通过各自验收；P1 若延期，发布说明逐项列出；
2. 所有 AI 写入路径都有“确认 + 撤销 + 审计”；
3. 未授权时 0 次网络外发；
4. 10 万篇基准达标；
5. 三平台安装/升级在真实设备上验证（至少 Windows / Linux 各 1 台）；
6. macOS 公证通过，自动更新签名校验通过；
7. 真机验收报告、CHANGELOG、GUIDE / MANUAL / UI_SPEC 同步更新。
