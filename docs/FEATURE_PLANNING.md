## 3. 知识图谱规划

知识图谱拆成三层，按依赖顺序推进：**双链数据 → 反链体验 → 图谱可视化**。
先做数据与反链，图谱视图才有意义；否则只是好看的线团。

### 3.1 数据模型

新增迁移 `003_note_links.sql`：

```sql
CREATE TABLE IF NOT EXISTS note_links (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,
    workspace_id   TEXT NOT NULL,
    source_note_id TEXT NOT NULL,
    target_note_id TEXT,              -- 解析不到目标时为 NULL（未解析链接）
    target_title   TEXT NOT NULL,     -- 链接原文，用于显示与后续重连
    target_anchor  TEXT,              -- [[笔记#小节]]
    link_type      TEXT NOT NULL,     -- wikilink | markdown | url
    context        TEXT,              -- 命中处的上下文摘要（≤ 200 字）
    position       INTEGER NOT NULL DEFAULT 0,
    created_at     TEXT NOT NULL,
    UNIQUE (source_note_id, target_title, position)
);

CREATE INDEX IF NOT EXISTS idx_note_links_source ON note_links(source_note_id);
CREATE INDEX IF NOT EXISTS idx_note_links_target ON note_links(target_note_id);
CREATE INDEX IF NOT EXISTS idx_note_links_title  ON note_links(workspace_id, lower(target_title));
CREATE INDEX IF NOT EXISTS idx_note_links_type   ON note_links(link_type);
```

要点：

- `note_links` 是**可重建的派生数据**，删除它不影响 Markdown 正文（符合「索引可重建」原则）；
- `target_note_id` 允许为空，用于「未解析链接」（dangling link），避免用户写了 `[[X]]` 却看不到反馈；
- 外链（http/https）以 `link_type='url'` 记录但不进入图谱，仅用于「出链列表」与失效检查（可选）。

### 3.2 解析规则

| 语法 | 含义 | 处理 |
| --- | --- | --- |
| `[[标题]]` | 双链 | 按标题解析目标 |
| `[[标题\|别名]]` | 带别名 | 显示别名，指向标题 |
| `[[标题#小节]]` | 指向小节 | 记录 `target_anchor`，打开时滚动定位 |
| `[[标题#^块]]` | 块引用（预留） | 记录锚点，V2 再实现块级定位 |
| `[文字](相对路径.md)`（示例，非真实链接） | 相对 Markdown 链接 | 按工作区相对路径解析 |
| `[文字](https://…)` | 外链 | `link_type='url'`，不入图 |

解析细节（必须写进实现与测试）：

1. **忽略代码**：围栏代码块与行内代码中的 `[[…]]` 不解析；
2. **忽略大小写与首尾空白**：`[[ SQLite ]]` 与 `[[sqlite]]` 视为同一目标；
3. **解析优先级**：标题精确匹配 → 文件名（去扩展名/时间戳前缀）→ 笔记 id；
4. **同名冲突**：命中多篇时按「同分类 > 最近修改」取一，并在反链面板提示存在同名笔记；
5. **重命名联动**：目标重命名后，用 `target_title` 反查并批量更新链接文本（可开关，默认开启）；
6. **删除联动**：目标进入回收站后链接标记为「已失效」，恢复后自动复活。

### 3.3 后端服务

新增 `application::link_service::LinkService`（沿用 `IndexService` 的写入时机）：

| 时机 | 动作 |
| --- | --- |
| 新建 / 保存 / 导入笔记 | 解析该笔记的出链，事务内重建其 `note_links` |
| 重命名 / 移动笔记 | 更新其它笔记指向它的 `target_note_id` |
| 删除 / 恢复笔记 | 把指向它的链接标记为失效 / 复活 |
| 外部文件修改 | 走同一解析路径（复用 `apply_file_changes`） |
| 重建索引 | 全量重解析（后台线程 + 进度事件） |

命令（沿用设计文档 14 章的命名风格）：

```text
links_get_backlinks(noteId)      -> Backlink[]        // 谁引用了我 + 上下文
links_get_outgoing(noteId)       -> OutgoingLink[]    // 我引用了谁（含未解析）
links_get_unresolved()           -> UnresolvedLink[]  // 全库未解析链接，可一键建笔记
graph_get(filter)                -> GraphData         // 节点 + 边，供图谱视图使用
links_rebuild()                  -> LinkRebuildReport
```

`graph_get` 的 filter：`{ categoryIds?, tagIds?, updatedAfter?, includeDangling?, includeIsolated?, limit? }`，
返回 `{ nodes: [{ id, title, categoryPath, tags, degree, updatedAt }], edges: [{ source, target, type }] }`。

### 3.4 前端交互

**M1（反链）**

- 编辑器底部/右侧「反向链接」面板：来源笔记标题 + 上下文摘要 + 点击跳转；
- 未解析链接在面板中高亮并提供「创建这篇笔记」按钮（创建后自动建立连接）；
- 笔记元信息栏显示「被 N 篇引用 / 引用 M 篇」。

**M2（编辑体验）**

- 编辑器输入 `[[` 弹出标题补全（CodeMirror autocompletion，数据来自标题缓存）；
- 预览态把 `[[标题]]` 渲染为可点击 chip，按住 ⌘/Ctrl 点击跳转；
- 搜索结果里显示「被 N 篇引用」，便于判断权威笔记。

**M3（图谱视图）**

- 独立页面 `/graph`：Canvas 2D 力导向布局（自研简化版或引入轻量 force 库）；
- 节点大小 = 度数，颜色 = 顶层分类；边的粗细 = 共现次数；
- 交互：点击节点打开笔记、双击展开邻居（1–2 跳）、拖动、缩放、聚焦某节点；
- 过滤：分类、标签、时间范围、是否包含孤立节点/未解析链接；
- 性能护栏：默认最多渲染 2000 节点 / 5000 边，超出时提示「先筛选」；
- 可选增强：按社区检测（Louvain 简化实现）着色、图上高亮搜索结果、导出 PNG。

### 3.5 里程碑与验收

| 里程碑 | 范围 | 验收标准（可测） |
| --- | --- | --- |
| M1（V1.1） | 数据表 + 解析 + 全量重建 + 反链面板 + 未解析链接 | 保存含 `[[A]]` 的笔记后，A 的反链立即出现；删除 A 后反链标记失效，恢复后复活；`links_rebuild` 后链接与正文一致 |
| M2（V1.1） | 编辑器补全、chip 渲染、跳转、搜索联动 | 输入 `[[` 出现候选；点击 chip 打开目标；目标重命名后链接自动更新 |
| M3（V2.0） | 图谱视图 + 过滤 + 聚焦 | 3000 笔记规模下图谱首屏 < 1.5s，交互 30fps 以上；过滤条件生效且可复位 |

性能目标：反链查询 < 50 ms（索引命中）；1 万笔记 / 5 万链接的全量重解析 < 10 s（后台线程，带进度事件）。

### 7.2 官方原文要点

1. **子文档语义**：在某个文档下新建，新文档**变成该文档的子节点**；顶部 `+` 新建则排到目录最上面
   —— 与我们的「创建子文档」一致；
2. **拖拽同时承担排序与改层级**：按住文档拖拽，「**蓝色横线**表示拖到的位置，
   **蓝色框**表示拖成为该节点的子级」；
3. **分组节点**：目录里可「新建分组」，把若干文档归到一个分组下（分组本身不承载内容）；
4. **条目「更多操作」**：「重命名、复制、移动、导出、删除等操作」；
5. **「移出目录」有独立归宿**：移出目录的文档进入知识库的**「全部文档」**，
   通过「…」→【目录管理】→【文档管理】→ 状态筛选「不在目录中」找回，并可**添加回目录**
   —— 语雀把「目录」与「全部文档」当作两个视角；
6. **目录管理页**：独立管理视图，支持搜索、新建、**批量复制 / 转移 / 删除 / 关闭分享**，
   且**批量删除后可撤销**；
7. **历史版本**：自动保存历史记录 + 手动「保存为版本」并命名 + **对比任意两个版本** +
   还原 / 访问指定版本 + 复制版本链接（链接分享部分我们不需要）；
8. **大纲**：按标题自动生成，默认固定在右侧；可「隐藏大纲」收缩为**贴边 mini 态**
   （鼠标滑过展开），也可「钉住大纲」固定；
9. **模板**：推荐模板 + 自定义模板（本知识库 / 团队 / 我的），可从文档「另存为模板」；
10. **导入格式**：Word(.docx/.doc)、Excel(.xlsx/.xls/.csv)、Markdown(.md/.markdown/.mark/.txt)、
    Zip、Evernote(.html+zip)、Lakebook；**Markdown 带图片需打包成 zip 再导入**；
11. **导出**：整库 → `lakebook`（≤200 篇，超时需拆分）；单篇 → word / Markdown / PDF / JPG；
12. **知识库定位**：文档 + 画板 + 数据表 + 表格四类编辑器；统计页含文档明细
    （近 30 天 / 近一年，可导出）；知识库可收藏；
13. **分享 = 协作邀请**：「分享给指定人」（对方成为协作者、站内信通知）与「公开分享」
    （游客可读，需会员）；文档可见性与知识库解绑（公开库内可有私密文档）；
14. **标签**：跨知识库整理，但仅在个人 / 团队内生效。
